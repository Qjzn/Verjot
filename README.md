# 听记 · Tingji

一个 Windows 会议录音与中文转写小工具。按快捷键开始，会议结束后得到 **一条 192 kbps MP3 + 一份 Markdown 转录**。录制时使用无损分段，转录和说话人分析使用无损音轨。支持普通文件夹和 Obsidian；无需设置窗口，安装与配置可以交给 AI。

会议控制使用托盘和 **186×68 的置顶浮窗**：左侧计时与录音输入波形，中间麦克风开关与输入反馈，上方收起，右侧纯红方块结束。正常录音时不显示「录音中」文字；任一路有实际声音时左侧波形跳动，安静时回落。关闭麦克风用划线图标表示，电脑声音继续录制；整场暂停时波形停止，并在左侧显示「已暂停」。收起后继续录音，双击托盘恢复。蓝色托盘图标表示就绪，红色表示录音。

输入波形平滑变化，按钮状态使用约 120–180 毫秒的短过渡。`animation_mode` 默认 `"auto"`，跟随 Windows 客户区动画及高对比设置；`"on"` 只为听记开启动效，适合系统关闭动画但希望听记保留动效的情况；`"off"` 关闭非必要动画。三种模式都不修改 Windows 设置，波形只反映真实输入，安静时不制造音量跳动。

| 操作 | 默认方式 | 效果 |
| --- | --- | --- |
| 开始 / 结束会议 | `Ctrl+Alt+L` | 同时收录麦克风与电脑声音；结束后自动转写。 |
| 暂停 / 继续整场 | `Alt+Space`，按一次切换 | 同时暂停两路声音；恢复时保留之前的麦克风开关状态。只在录音期间占用此快捷键。 |
| 标记重点时间 | `Ctrl+Alt+K` | 录音中记下当前会议时间，转录中生成「重点时刻」；也可从托盘或浮窗右键操作。 |
| 展开 / 收起速记便签 | `Ctrl+Alt+J` | 独立的置顶便签，每天一篇，收起前保存；不改变录音状态。 |
| 关闭 / 开启麦克风 | 点击浮窗麦克风 | 只影响听记的收录，电脑声音继续录制；不改变会议软件的通话。 |
| 收起 / 展开浮窗 | 上方箭头 / 双击托盘 | 录音持续进行。 |
| 查看处理结果 / 重试 | 托盘「最近会议」 | 按会议时间选择对应笔记、录音资料或失败重试；复用已完成片段，保留手写区内容。 |
| 会后快速命名 | 所选已完成会议的「命名这场会议」 | 在小输入框填写标题，修改 Markdown 文件名及会议标题；不改动录音，重名不覆盖。 |

四个快捷键均可通过 `hotkey`、`pause_hotkey`、`bookmark_hotkey`、`quick_note_hotkey` 自定义，不能相互冲突；暂停和标记快捷键仅在录音时注册。辅助快捷键被占用时会指出对应键，录音仍能开始，可从右键菜单操作。浮窗空白处或录音按钮右键可打开与托盘相同的操作菜单；结果路径的右键仍用于复制完整路径。

## 速记便签

`Ctrl+Alt+J` 展开或收起听记内置便签，也可从托盘「速记便签」打开；原有 `Ctrl+Alt+L` 录音操作不变。速记快捷键被占用时会提示，仍可从托盘打开，不妨碍录音。便签使用原生 WPF，首次打开时才加载；默认置顶，初始尺寸为 360×420 逻辑像素，可调整大小。`Esc`、关闭按钮均收起便签。窗口位置、尺寸等本机设置不写入笔记库。

每天的文字保存在 `vault_root/速记/yyyy-MM-dd.md`，可用 `quick_note_folder` 改目录。可粘贴截图，或粘贴/拖入可解码的本地图片文件；图片转为 PNG，保存到 `速记/图片/<内容哈希>.png`，正文使用相对 Markdown 引用，同一图片内容复用文件。单个源文件及转换后 PNG 均不超过 12 MiB，像素不超过 3600 万，多帧图片只取首帧。普通文件夹与 Obsidian 都可使用，不依赖 QuickAdd 或 Obsidian 浮窗。

编辑停顿 500 毫秒后，后台依次保存恢复草稿和正文，慢盘保存期间仍可继续输入和拖动；新输入合并为最新待存版本。收起和退出会等待最新内容保存完成，不阻塞界面等待。发现笔记被外部修改或删除时提示冲突，不覆盖外部内容；点击底部提示可打开速记文件夹、复制当前内容、查看草稿，或保留草稿后载入磁盘版本。草稿也无法落盘时，内容仍留在窗口，应先复制保存。保存失败或输入法组合尚未提交时，保留编辑器并取消本次退出，不会先停止录音。更新程序时一并保留库外的 `work/`。

图片粘贴只读取该次粘贴事件的数据，不主动写入、清空或备份恢复系统剪贴板；只有主动复制或剪切才会更新剪贴板。图片编码与落盘在后台完成，处理期间可继续输入；最多同时排队 16 项，剪贴板图片的待处理像素总量不超过 3600 万。拖动标题区域会实时移动便签，不受 Windows「拖动时显示窗口内容」开关影响，也不修改系统设置。回归测试使用内存图片与独立测试桌面，不读写真实剪贴板、不向当前窗口注入按键。

若曾安装独立的 `ObsidianQuickNoteHotkey.exe`，先停用它及其「Obsidian 速记快捷键」登录启动项，避免占用同一组合；保留既有速记笔记，不用历史 QuickAdd 备份覆盖现有配置。

浮窗尺寸为 **186×68 逻辑像素**，随 Windows 缩放，使用原生高 DPI 支持避免整体位图放大。构建会嵌入 `app.manifest`，并生成配套的 `ObsidianMeeting.exe.config`；更新时须一起保留，不能只复制 EXE。

默认跟随 Windows 默认麦克风，并收录**所有活动播放设备**的电脑声音，覆盖会议软件与媒体被分配到不同设备的情况。已有活动输出在默认设备切换前就开始捕获；麦克风默认设备变化时切换到新输入，保持麦克风开关和整场暂停状态。新增或重新启用的设备需要初始化，不能承诺初始化前的声音也已录下。也可通过 `system_capture_mode: "default"` 只跟随默认播放设备，或用设备 ID 固定输入/输出。悬停查看设备与输入状态；`notify_device_changes: false` 只关闭变化提醒，不关闭跟随。暂停区间保留静音，重点标记和转录使用同一会议时间轴。

采集直接使用 WASAPI 包的设备位置和 QPC 时间戳，以共同时间轴写入各轨，不再把回调迟到当成新静音。连续设备帧保持相位连续，用较长窗口轻量校时，避免将短期时间戳抖动变成静音洞；停止时排空边界前数据。时间戳异常或数据中断会保留诊断，不用相同 WAV 长度冒充同步成功。受保护、独占音频和设备故障仍可能无法录制，实际设备与长会议验证范围见[质量说明](documentation/quality.md)。

两路持续无声默认满 60 秒提醒一次，帮助发现忘记播放或选错设备；有声音恢复后才重新计时。关闭麦克风时只根据仍在录制的电脑声音判断；整场暂停不触发。`silence_warning_seconds` 可设为 `0` 关闭。提醒是输入状态提示，不把安静认定为录音失败。

## 结束后与异常恢复

结束录音后，原有浮窗改为两行处理状态，隐藏麦克风和结束等录音按钮，仍可收起。等待动画表示后台正在处理；阶段名称和片段数只采用实际状态，动画不代表音频输入或整场百分比。托盘持续显示正在执行的阶段；已经取得片段总数时显示真实完成段数。开始下一场时浮窗与托盘优先显示当前录音，悬停可查看后台任务数量。

完成后小窗两行分别显示「录音：<相对路径>」「转录：<相对路径>」，直接展示实际保存位置。路径相对于配置的保存根目录，长路径优先省略目录，文件名仍过长时省略其中间部分并保留扩展名；悬停查看完整绝对路径，点击在资源管理器定位该文件，右键复制完整路径。托盘「最近会议」也可分别定位所选场次的 MP3 和 Markdown，旧会议仍可定位其 WAV。

托盘「最近会议」用精确到秒的会议时间标识各场状态，打开笔记、查看录音资料和重试都对应所选那一场。菜单最多显示 20 场，优先包含需要关注的记录；更早的本机资料可从 `work/` 查看。上一场失败后即使已经开始下一场，重试也不会改指向新录音。转写完成时，只有启用 Obsidian、允许自动打开且当前没有录音，才自动打开刚完成的笔记；录音中完成的会议从托盘手动打开，不切换当前前台窗口。

命名仅用于已完成且没有运行中转写进程的会议；正在录制另一场时入口禁用，避免弹窗打断。命名后历史显示「会议时间 · 标题」，Markdown 与其管理元数据保持一致；同名文件不会被覆盖，已有手写内容保留。重点时刻使用从本场开始起的墙钟时间，包含整场暂停时间，与录音、转录时间轴一致。

手动清理已成功完成的会议时，只删录音文件会显示「仅保留转录，录音文件已移除」，只删 Markdown 会显示「仅保留录音，转录文件已移除」；保留剩余文件的入口，不作为故障提醒，也不自动重试。两份都删除后，该场不再出现在最近会议中。采集、发布、校验或清理异常、路径不明、保存根目录不可用仍提示检查。程序保留内部状态文件，不自动删除或重建你的成品。

启动时检查本机 `work/` 中的会议状态。仍在运行的原转写进程会被接回，不重复启动；工具退出期间已完成的会议提供结果入口，失败的会议在存在原始录音时提供对应重试。需要关注的同一可读状态只提示一次；重试或状态改变后可以再提示。JSON 或路径异常无法安全记录提示状态时，每次启动仍会提醒检查。开启处理浮窗时用原小窗展示提示。中断录音只提供状态与资料检查入口，不能直接按普通失败任务重试；不自动继续录音、修复文件头、删除原资料或上传旧录音。文件是否可恢复需要先检查，不能保证任何中断都能完整找回。

三项反馈可通过 `show_processing_window`、`notify_device_changes`、`auto_open_completed_note` 控制，省略时均为 `true`。旧配置省略 `animation_mode` 时采用 `"auto"`，其他已确认字段保留原值。`show_processing_window: false` 不自动显示会后浮窗，结束时收起已有窗；仍可从托盘手动展开状态和结果，后续阶段刷新不会把手动展开的窗关闭。

## 交给 AI 安装

把下面这段需求连同源码目录交给你的 AI：

> 请按 `documentation/ai-install.md` 安装听记。先核对保存目录、local/api 模式与已有环境，运行 `Install.ps1 -Plan`，再执行安装。保留已有配置和会议；密钥仅使用环境变量。完成后运行 doctor，说明实际验证与未验证的部分；不要默认修改开机启动。

完整步骤见 [AI 安装说明](documentation/ai-install.md)。配置字段、默认值、示例与排障见 [配置说明](documentation/configuration.md)；机器可读约束在 [config.schema.json](config.schema.json)，首次配置模板为 [config.example.json](config.example.json)。

需要 **Windows 10/11 x64、Python 3.12 x64、.NET Framework 4.8**。以下命令在源码目录执行，保存位置请换成自己的路径：

```powershell
# 先看计划；不下载、不创建配置、不修改启动项
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1 -NotesPath 'D:\Meetings' -Mode api -Plan

# 确认模式后安装；API 服务参数还需按配置说明补齐
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1 -NotesPath 'D:\Meetings' -Mode api
```

本地 CPU 模式改为 `-Mode local -Backend cpu`；NVIDIA CUDA 环境可选 `-Mode local -Backend cuda128`。首次使用 Obsidian 加 `-UseObsidian`，需要登录自启才加 `-StartWithWindows`。安装器保留现有 `config.json`；已有 Torch 后端与参数不一致时会停止，需按实际环境选择参数。安装过程不启动录音，也不调用 API。

首次 API 安装会留下模板，服务地址和模型名未填写时自检失败并返回非零退出码。补齐配置与密钥环境变量后重跑安装，不能把模板生成当作安装就绪。

## 选择转写方式

| 模式 | 中文转写 | 本机安装与数据流 |
| --- | --- | --- |
| `local` | Qwen3-ASR-1.7B | 下载识别与说话人模型及 PyTorch 等依赖，体积为数 GB；会议处理离线完成。GPU 更适合长会议，CPU 速度需要在目标机器实测。 |
| `api` | 用户配置的语音转写服务 | 不装本地 Qwen、Torch、Transformers；仍安装小型说话人模型及音频处理依赖。讲话片段上传所选服务。 |

API 兼容 **`POST /audio/transcriptions`**，使用 WAV、`model`、`language=zh` 和 JSON 文本返回。普通聊天模型能否用作语音转写，必须以供应方实际支持的这个端点为准。服务地址填写含版本路径的前缀，如 `https://provider.example/v1`；密钥通过 `api_key_env` 指定的环境变量读取，配置里不放密钥值。

两种模式都在本机用 sherpa-onnx / 3D-Speaker 做说话人分组。目标是**同一人在两路上使用同一编号，不同人分开**：直接比较两路可靠讲话片段的声纹，联合分组，并要求组内片段彼此相符，避免先把局部编号当成不可拆分的身份。短段、重叠或身份区分不足显示「说话人待确认」，不强行分配身份。新会议的回放录音合并为一条 MP3。设备声道差异、噪声和串音可能造成误并或漏并，当前不保证全部编号正确；转录不推断真实姓名，不自动生成会议结论。

`asr_denoise` 默认 `"light"`，只对送入识别的片段副本做轻量低频处理（零相位 70 Hz 高通）；`"off"` 关闭。保存的会议录音不应用这项处理。这不是全频降噪，也没有证据证明它能普遍提高中文准确率；建议使用同一段实际会议对比后选择。

`asr_echo_filter` 默认 `true`：只有麦克风片段与电脑声有高置信延迟波形证据、多个窗口一致、时间覆盖充分，并且最终转写文字完全相同，才在 Markdown 中保留电脑声那一份。短应答、文字不同、独立复述和证据不足的片段继续保留。关闭设为 `false`。这项功能不修改保存的会议录音，不能代替声学回声消除或多人声音分离；说话人归属也不因回声候选而强行统一。

模型在会议结束处理时加载。模型下载、运行库和个人配置保存在安装机器上，**不放进 Git 仓库**。API 模式也并非完全没有本地模型。

## 文件与配置

首次安装默认写普通 Markdown，不要求 Obsidian。开启 `open_in_obsidian` 后采用 Obsidian 音频引用；是否自动打开由 `auto_open_completed_note` 和当前录音状态共同控制。旧配置省略这些字段时保留 Obsidian 输出和空闲时自动打开。更改配置请先结束录音、等待转写并退出托盘，然后重启。

```text
保存目录/
└─ 会议记录/
   ├─ 2026-10-14 14-30-00.md
   └─ 附件/20261014-143000/meeting.mp3
```

“附件”是唯一录音的保存目录，MD 引用同一 MP3，不会再复制音频。临时无损分段、RF64 混音、识别片段和日志在程序的 `work/`；正常成品验证成功后清理，笔记目录只留上述两份文件。采集异常即使转写完成也保留核查资料，显示「采集异常 · 检查录音」，不以转写成功保证声音完整；仍可打开两份成品。失败时保留本机恢复资料，便于重试。`work/` 内的 `controller.json` 仅记录本机进程身份与提示状态，用于接回任务和避免重复提示，不是额外会议附件。

新转录去掉「录制时间、时长、转写引擎」模板行、空的「我的笔记」和 HTML 管理标记，保留录音入口、正文、适用的重点时刻和暂停区间。内部状态记录自动生成正文的范围与校验信息；重试保留范围之外的手写内容，检测到范围内被用户改动时停止覆盖。带旧标记的笔记可在安全重试时迁移，不批量重写历史笔记。说话人分组限制提示暂时保留，直到录音与转录质量标准得到确认并有对应验收证据；当前测试范围见 [质量标准与证据](documentation/quality.md)。

## 自检、验证与更新

```powershell
.\.venv\Scripts\python.exe -B tingji.py doctor --full --json
.\.venv\Scripts\python.exe -B tingji.py status --json
.\.venv\Scripts\python.exe -B -m unittest test_tingji_config test_api_asr test_meeting_worker test_merge_audio test_prepare_audio -v
# 完整源码回归：Python + 编译执行原生控制器、浮窗和会议目录测试
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test.ps1
```

`doctor` 检查配置、依赖、模型文件、写入权限与空间；`--full` 进一步导入依赖并检查音频设备，始终不录音、不加载识别模型、不调用 API。健康退出码为 `0`，失败为 `2`。`status` 读取最近一次会议的处理状态。自检通过后，仍需用一段明确授权的音频验证目标机器的真实输入、输出和转写服务。

自动化回归覆盖配置、API 请求与断点恢复、混音时间轴、原子发布、成品校验和手写区保护。原生回归覆盖按会议重试、进程接回、启动恢复提示、两路输入反馈和轻量处理浮窗。真实硬件切换、API 供应方与全新机器安装需分别验证；模拟接口和界面测试不能证明供应方可用、中文准确率或目标机器的设备行为。

运行 `ObsidianMeeting.exe` 启动听记，此文件名为兼容现有快捷方式保留。开发更新可用 `Build.ps1 -OutputPath ObsidianMeeting.next.exe` 生成候选；构建需要同版 `ObsidianMeeting.cs`、`SessionCatalog.cs`、`MeetingActions.cs`、`app.manifest`、应用配置与图标资源。构建同时生成候选名对应的 `.exe.config`，安装为正式文件名时也须对应改名为 `ObsidianMeeting.exe.config`。更新前完成会议及转写并正常退出托盘，保留本机 `config.json` 与 `work/`。`assets/Create-Icons.ps1` 可重新生成图标。

旧版附件整理工具默认只规划：`Compact-Completed-Meetings.py`；未合并但完整的旧记录可先用 `Prepare-Legacy-Merged-Meetings.py`。实际变更需明确传入 `--apply`，后者还要求 `--only-session` 名单。只清理已验证的生成文件，未知文件与缺少成品的记录保留。

录制时默认每 300 秒按精确帧切为一个原设备格式的无损 WAV 段，另有单段安全字节边界；切段不重启设备、不重置时钟、不删掉暂停时长。同一设备各段仍是一条逻辑音轨，避免交界讲话被拆成不同来源。混音使用支持大文件的临时 RF64，随后流式编码 MP3。`recording_segment_seconds` 可设 10–600 秒；`mp3_bitrate_kbps` 默认 192，可选 128、192、256、320。192 kbps 成品约 86.4 MB/小时，临时无损音轨仍需要空间。

成品清理前核对 MP3 的全部音频帧码率、完整解码长度与内容摘要，并核对 Markdown；已有发布目标须匹配本场记录，避免覆盖其他录音。正常成功后清理无损分段、RF64 混音和识别片段，只保留一条 MP3、一份 Markdown，以及工作目录内必要的控制元数据。失败或采集异常时保留恢复资料。旧 WAV 会议不自动转换。分段不解决磁盘写满、驱动丢音或转写全轨内存占用；实际验证与边界见 [质量说明](documentation/quality.md) 和 [隐患审查](documentation/risk-review.md)。

产品边界与后续小功能候选见 [产品范围](documentation/product-scope.md)。第三方条款见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
