# verbit：发布验收清单与真实边界

保留小浮窗和会后处理。以可恢复的录音、可核对的转写、可重复安装为发布依据。已有短录音、合成测试或本机输入体验结果，只能支持各自覆盖的场景；不要概括成数小时稳定或说话人完全准确。

## 每版固定验收

| 优先级与检查 | 方法及通过证据 | 当前边界 |
| --- | --- | --- |
| P0：正常长会 | 分别录 30、60、120 分钟，麦克风与电脑声均有已知标记；记录每段帧数、合并长度、首尾标记及 MP3 全解码；逐交界比较原始轨与混音，Markdown 指向唯一成品。 | 需要用户授权真实采集和回放；历史约几十秒分段结果不能替代。 |
| P0：暂停/恢复 | 在已知标记期间单独关闭麦克风、整场暂停，各至少三次；核对电脑声在关闭麦克风时持续、整场暂停时两路静音、恢复时边界及真实会话时间线一致。 | 录音内真实内容及可接受边界应人工记录，不能只看按钮变化。 |
| P0：切换/断开 | 默认输出在耳机/扬声器间切换，拔插 USB 麦克风与蓝牙重连；记录设备事件和信号实际恢复时点，逐来源核对。 | 已有部分切换证据；新设备初始化仍可能缺音，不宣称无缝。不得在未授权时改变用户设备。 |
| P0：异常可恢复 | 在隔离虚拟磁盘或故障注入中验证磁盘满、休眠/恢复、采集失败及程序意外退出；检查异常提示、有效前缀、残留资料与重试路径。 | 自动写入故障注入不能替代真实磁盘/驱动；不得填满系统盘或终止用户会议。 |
| P0：首次可用 | 干净 Windows 10/11 x64，用发布包及说明让另一个 AI 安装；先 doctor，再经授权运行 first-use.md 的真实录音、回放和实际本地/API 转写，交付真实文件路径。 | 当前没有干净机器与所有 API 服务商通过的证据；doctor 不加载模型、不会调用 API。 |
| P1：中文/说话人 | 有逐字稿、真实身份与时间标注的固定中文样本，分别覆盖安静、噪声、口音、专名数字、跨设备、同人跨轨和重叠讲话；逐版记录字错率、同人误拆、异人误并、未知覆盖及重复正文。 | 仍缺足够人工标注的会议级统计；合成变声/单条成功不能当身份准确率。模型和阈值不在未测时宣传达标。 |
| P1：资源与响应 | 每个阶段记录峰值内存、磁盘峰值与耗时；同时由用户在真实速记入口输入、贴图、拖动，再核对图片重开与自动保存。 | 模型会后加载不等于全程低内存；转写准备仍有整轨数组，需先测再决定分块优化。 |
| P1：更新与回退 | 新版保留原配置、快捷键和笔记；旧录音按原格式可访问；显式回退时核对 EXE/config 配套及成品无变化。 | 不默认迁移或删除个人配置；旧版不理解的新字段需先验证兼容性。 |

每条证据至少记录：源码提交/构建哈希、Windows 和音频设备、模式与模型/API 名称、明确授权范围、样本来源及逐字稿、实际步骤、预期、结果、异常和证据路径。不记 API 密钥，不把原始录音/正文直接提交 Git。用户取消或权限不允许时标“未验证”，不能记“通过”。

## 稳定与高质量分别验收

稳定性关注录音是否持续、文件是否可恢复、时钟是否正确、程序是否响应；转写质量关注内容和说话人是否准确。MP3 全解码、段帧数连续及能量非零是必要技术证据，但既不能证明外部声音未漏，也不能证明中文和身份正确。

用户要求准确识别同一人在两路音轨中的身份、避免不同人合并、完整记录电脑声与开启麦克风期间的声音，并适当降噪。这些是目标，当前不能由未标注样本证明已达到。具体字错率、身份准确率、边界偏差和等待时间指标需在真实样本基线后共同确定；没有默认认可的百分比。重叠讲话与未知身份单独报告，不能靠隐藏文字限制获得“通过”。

新版本发布说明应列出本轮改变、实际覆盖、未验证设备/长会议/云服务、升级和回退步骤。2026-10-16 用户已选择项目源码采用 MIT，根目录 `LICENSE` 已补齐；仓库继续保持私有。第三方依赖、模型、FFmpeg 及其编译选项对应的打包分发审查仍须独立完成，项目源码的 MIT 不替代这些条款；把私有仓库改公开本身不完成发行审核。
