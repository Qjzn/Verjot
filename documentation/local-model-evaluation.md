## 安装边界

评估与正式 `.venv`、`models/` 分开。当前本机使用两个独立包覆盖环境，只读复用已安装的 PyTorch，新增包落在各自环境中；它们依赖本机原环境，因此不能复制到另一台电脑就宣称独立可运行。新电脑需要另建 Python 环境并单独安装匹配的 PyTorch/TorchAudio；干净 Windows 安装仍需独立验收。

当前评估基础为 Python 3.12、PyTorch/TorchAudio 2.11.0+cu128，FireRed 补充 kaldiio、kaldi-native-fbank、sentencepiece、cn2an 与 TextGrid，Community-1 使用 pyannote.audio 4.0.7。FireRed 官方示例原本固定较旧的 PyTorch，不能直接把整份官方 requirements 覆盖安装进正式 Qwen 环境。依赖检查、导入与实际推理兼容性分别记录。

只下载选用的 AED 权重，不安装额外的 LLM、VAD、语种识别或标点模型。官方 AED 检查点约 4.73 GB；不能把约 1B 参数解释为只有几百 MB 下载。模型与依赖不进入 Git 仓库或默认安装包，推理结束后进程释放模型。GPU 推理逐个运行，限制 CPU 线程数，不与另一候选模型同时占用 GPU。

本轮固定 FireRed 官方代码提交 `4e7d9aaf4482a47cec1724807026b9b151926eb5`、权重提交 `2304afed56eacfee6256dee5937ed22ffa0b64ec`；检查点 SHA-256 为 `4677cbd30988d63ed3e777f6a42a1e5260a3865317f6e15e488bef40954f7054`，在反序列化前与官方文件元数据核对。复跑应同时记录代码、权重、解码参数和输入分段，不能只写模型名称。

本机19段同音频、无提示的小样本中，Qwen 总耗时约30.19秒、峰值 CUDA 分配4069 MiB；FireRed 官方加载加 mmap 约43.35秒、峰值分配2375 MiB，但进程工作集峰值8993 MiB。候选改用 `accelerate.init_empty_weights(include_buffers=False)`、`load_state_dict(assign=True)`，核对无缺失/额外权重并恢复原模型共享的投影权重，随后直接以 BF16 转入 CUDA；最终同19段约20.08秒、工作集峰值5369 MiB，峰值 CUDA 分配仍为2375 MiB，19段文字与原加载逐段一致。这只验证该批样本的加载内存和输出一致性；不是全面等价证明、干净机器结果或整场加速比例，尚未改正式加载器。

AED 对照不安装独立标点模型，结果通常不带标点；不以去标点后的文字分数代替最终阅读体验。当前组合不请求逐字时间戳，也不能把新 TorchAudio 环境中旧对齐接口的回退结果当作已验证的字级对齐。

## 对照方法

1. 保护原录音、Markdown、无损来源与既有结果。候选目录独立保存，前后检查哈希；不调用录音发布、原笔记写入或成功清理逻辑。
2. 先只换 ASR：复用同一组已准备的无损 WAV 与原 MP3 的现有分段。固定解码参数，模型提示内容单独记录；对比文字时不修改原声、强制替换术语或向模型提供竞品正文。
3. 再只换说话人流水线：用原 MP3 的本地解码副本运行完整 Community-1，不指定人数，不把各轨独立编号直接拼在一起。合并音轨的标签不是麦克风来源标签，人物身份仍需与原无损轨对照。
4. 检查同人拆分、异人误并、重叠发言和本人的近似参考时间窗。背景其他人不当作单一身份，不把全部麦克风声音绑定本人。保留普通及重叠时间线，不用排他输出冒充恢复了重叠讲话。
5. 只有人工核对过的文字和人物时间线才用于 CER/DER 或正确率。竞品参考的字符编辑距离、匿名编号数、待确认数和模型重复输出只作核对线索，不作为准确率。

模型下载阶段不读取会议音频。推理阶段设置 Hugging Face 离线、关闭遥测，并在独立 Python 进程安装网络连接守卫；向模型传本地数组，不传音频 URL。记录被阻止的联网尝试、耗时、峰值显存及失败断点。Python 连接守卫不是 Windows 防火墙或整台电脑的网络审计。

## 2026-10-17 整场对照

本次使用约84分钟的同一场真实中文会议，分别复用既有无损双轨准备的588段 WAV，以及原 MP3 准备的561段 WAV。FireRed 不附加术语提示；整场 Qwen 复用此前带既有术语策略的基线，因此不是提示条件完全相同的模型排行榜。19段另做了同音频、均无提示的实际对照。

无损588段均处理完成，耗时511.33秒，峰值 CUDA 分配2382 MiB、进程工作集5369 MiB。FireRed 有11个短片段输出空白，其中4个来自麦克风、7个来自电脑声；需要回听区分漏识别、填充词省略和另一模型对噪声生成文字，不能直接称为11处漏音。未出现解码长度到限或输入文件改变。

同无损输入的去标点空白正文，Qwen 为21102字符、FireRed 为20794字符；与未逐句核验的竞品参考之间，字符编辑距离分别为3094与3161。它只说明 FireRed 在该指标上没有更接近参考，不能换算为中文准确率。小样本中有短语从不合语境的文字变得合理，也有业务词变差；现有证据不足以整体替换 Qwen。

原 MP3 对照561段也全部完成，耗时689.94秒，峰值 CUDA 分配2382 MiB、进程工作集5368 MiB；7段输出空白，正文20720字符。Qwen 同 MP3 基线为21025字符、0个空白段，与参考的字符编辑距离3030；FireRed 为3141。同样没有整体优于既有基线的证据。两组候选都检查了输入 WAV 与分段文件未改变、解码未到长度上限，进程网络守卫未记录连接尝试；它们不替代人工文字核验或历史采集完整性验收。

本轮未更换说话人流水线，因此没有新的同人拆分、异人误并或本人麦克风身份改善结论。当前默认路径仍有大量待确认与跨参考身份共享标签的核对线索，不能用 ASR 跑完或文字变好来宣称人物识别通过。候选结果和逐段回听链接仅留本机，未改写原会议。

## 当前决定

在候选取得实测改善证据之前，保持 Qwen 和已有说话人路径为正式默认。Community-1 账号授权、模型运行、中文逐字核验及人物核验分别验收；任何一项未完成都明确保留缺口，不用安装成功代替质量通过。完整会议正文、音频、声纹向量、人物姓名及个人配置仅保存在本机验证目录。
