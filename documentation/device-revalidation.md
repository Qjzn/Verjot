# 集中设备复验

此入口只供维护者验收，不进入基础安装包，不改变正式快捷键、模型或录音。音频、人物和逐包日志留在本机，不能提交到 Git。

## 准备与开始

在仓库根目录，用已知中文 PCM WAV 准备一个全新的隔离目录：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Prepare-DeviceRevalidation.ps1 -SpeechPath 'C:\Validation\known-a.wav'
```

准备只构建程序、复制合成样本并写配置，不采集、不播放。输出含 `preparation.json`、未修改的生产编码器、只记录包元数据的采集副本和“开始复验.cmd”。脚本严格匹配五个插桩位置，锚点变更时停止，不猜测补丁。

先向参与者说明约 2 分半的步骤并取得当次同意。暂停其他音频，保存速记、结束正式会议并等转写完成，再从托盘退出。启动输出目录中的“开始复验.cmd”，窗口出现时仍未录音；点击明确的开始按钮，倒计时 5 秒后采集。关闭窗口提前结束会正常保存本轮资料，记为提前结束，不算崩溃，也不自动重录。

| 录制时间 | 配合动作 |
| --- | --- |
| 0–15 秒 | 保持当前播放设备，确认测试音是否可听。 |
| 15–35 秒 | 按窗口提示完整读测试句，预留 20 秒。 |
| 35–45 秒 | 工具只关闭麦克风，电脑声继续；可说关闭验证句。 |
| 45–60 秒 | 麦克风恢复，再说一句恢复验证句。 |
| 60–85 秒 | 手动切到可外放扬声器并保持，68 秒附近播放已知样本。 |
| 85–110 秒 | 手动切回耳机并保持，95 秒附近播放样本。 |
| 110–135 秒 | 有第二支麦克风时手动切换并发言，没有则标为未测。 |
| 135–150 秒 | 最后一次播放，随后自动停止。 |

工具不设置 Windows 音量或默认设备。结束后由参与者恢复原设备；报告保留初始和最后的各角色默认端点快照，不能只根据“切换过”推断已经恢复。蓝牙通信角色与普通输入角色可能不同，需分别读日志。窗口仍可随时关闭，不要求参与者强行走完。

## 分析与边界

完成采集后，在有测试依赖的开发环境执行：

```powershell
.\.venv\Scripts\python.exe -B .\tests\AnalyzeDeviceRevalidation.py '<输出目录>\runtime'
```

分析拒绝读取正在录制或不属于该隔离目录的会话；只读分段和逐包时钟，输出 `device-analysis.json`。检查清单连续性、WAV 帧数、麦克风关闭区间内部静音、已知声音匹配、包时间戳估计和真实设备位置缺口。保留原始位置与修正后位置，不能把估计当成精确硬件时钟。

已知样本只在对应播放请求附近匹配，排除接近静音的数值噪声，相关门槛固定为 0.80。播放请求不等于用户听见，也不证明系统完整播放。麦克风和电脑声同时匹配到同一标记时，分别报告相对延迟，其中包含声学传播和硬件延迟；没有共同标记时列为未测，不能用合成测试替代。

然后对这一本轮隔离会话调用未修改的原生导出和本地转写，核对 MP3 完整解码、哈希、Markdown 引用以及清理状态。正常处理仅保留两个成品；有采集异常则原轨保留，说明原因。分析脚本不会自行开始转写、联网或重录，最终验收仍需结合参与者反馈。插桩会增加少量日志写入，单轮结果不能外推为长期稳定性。
