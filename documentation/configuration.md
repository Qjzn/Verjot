# Verjot 配置说明

2026-10-30 最终名称为 Verjot，取代旧名 verbit 和本轮临时名 Verlog。显示名和新会议前缀使用 Verjot，旧 `verbit-v1` / `Verlog-v1` 会话及文件名继续读取，保存目录、配置和笔记不改写。更新优先读取 `VERJOT_GITHUB_TOKEN`，未设置时依次兼容 `VERLOG_GITHUB_TOKEN` / `VERBIT_GITHUB_TOKEN`。Logo、安装 AppId、单实例锁及 `pianyan://` 协议不变。

默认仅录音，不下载推荐模型。新用户 API 可留空，选择“录音＋转写”才需完整地址和模型，密钥在实际转写时校验。新 API 直接上传校验后的 MP3，原生运行，无需 Python / 本地模型；旧模型和配置文件保留，桌面端不再连接内置本地引擎。

新文件目录示例：`<保存目录>/Verjot/Verjot202610271430/Verjot202610271430.mp3`；成功转写后同目录增加 `.md`，同分钟重录加序号。新 API 仅录音校验成功后清理临时分轨，稍后可从 MP3 转写；采集异常、处理失败保留恢复资料。旧文件不改。

接口使用 multipart `/audio/transcriptions`，默认 `response_format=json`。模型 ID 自定义，响应支持 `text` 或带 `start/end/text` 的 segments，可选 speaker/speaker_id；不保证供应方说话人功能。API 的降噪、身份识别与模型效果由供应方决定；旧本地降噪/回声字段仅保留历史可读性，API 处理由所配服务负责。实际配置方法、密钥设置、大小限制和失败重试见[安装说明](install-windows.md#启用会议转写)。`transcription_mode` 缺省为 `api`，默认不开启转写；保留 `local` 枚举仅供读取旧配置。

## 默认仅录音，转写按需开启

`auto_transcribe` 默认 `false`。速记、录音和 MP3 导出无需 Python、模型或网络。需要文字时，在「设置 → 转写」选择“录音＋转写”，填写自己的 `/audio/transcriptions` 接口地址、音频模型 ID、密钥变量名和超时。也可以关闭自动转写，稍后从最近会议手动转写。

只提供显式 API 配置，不探测、下载或自动连接本地模型；自行部署的本机模型也必须通过兼容 API 连接。原有模型、旧 `local` 配置及录音均保留。打开、取消设置不会改文件；旧配置需要在设置中确认保存 API 选择后才能转写。保存旧本地配置时自动转写默认关闭，需主动开启并填写 API。准备好接口不会自动续转旧会议，仍须选择该场并确认提交。

开始录音不检查密钥、不请求 API。结束时先生成并校验 MP3；开启自动转写但配置缺失时提示“录音已保存 · 待配置转写”。转写前明确确认地址与模型，取消后录音保留。新 API 流程只上传校验后的 MP3，服务端决定文字准确率与说话人能力。只有地址由你配置为本机且服务不外发时，音频才完全留本机。

旧版无新导出清单的会议不自动迁移到新 API 或覆盖原文件；桌面端会保留资料并提示使用已有 MP3 单独转写。已有完整转写检查点不允许悄悄换服务或模型。成功校验后清理临时资料，失败保留恢复文件及原因。

## 设置窗口

在托盘或录音浮窗的右键菜单选择「设置…」。常规页可更改保存位置、四组快捷键、录音保护时间、登录 Windows 后自启和自动检查更新。转写页可修改 `auto_transcribe`、`transcription_mode`、`api_base_url`、`api_model`、`api_key_env`、`api_timeout_seconds`、`asr_terms`、`asr_context`；旧降噪与回声字段保留但不由客户端 API 路径执行。设置不显示或写入 API 密钥，只引用你在 Windows 用户环境变量中设置的变量名；设置可以先保存，实际转写前再检查密钥；启动转写时读取当前 Windows 用户环境变量，不要求重启托盘程序。

浮窗顶部 Logo 与 Verjot 整组居中，点击 Logo 展开或收起，右上角 X 仅隐藏浮窗；下方待机时保留速记、录制和设置图标，按钮悬停仅显示操作名及当前快捷键，设置没有快捷键。处理、待配置或异常状态不显示常驻小字；Logo/名称悬停仅显示简短状态，实际进度和完整原因通过托盘查看，恢复资料保留。可重试的当前会议在右键菜单提供「重试当前转写」。

设置不再探测本地模型或提供本地引擎选项。API 会向你填写的地址发送音频，只支持音频转写接口；不保证仅填写聊天或 Omni 模型名即可使用。历史音频与说话人参数保留，不启用实验引擎。


`check_updates` 为布尔值，默认 `false`。开启后启动时及每24小时查询 GitHub Releases，后台错误不弹窗打断会议。不发送音频、笔记、配置或机器标识，只提示可安装的新版本，不擅自下载安装。手动更新与私有仓库授权见下文。

## 窗口内更新

在「设置 → 关于与更新」点击「检查并更新…」，看到目标版本和大小后点击「下载并更新」。下载、SHA256 / 大小 / 安装包内部版本校验在窗口内进行；可以取消下载。录音或转写尚在进行、速记尚未保存、输入法未确认或设置有未保存修改时暂缓安装，已下载的包可重试使用。

满足条件后程序自行正常保存并退出，独立的小更新窗口安装、验证程序清单并重新打开 Verjot。安装时不强杀、不自动重启电脑；开始安装后不能中途取消。安装失败会尝试恢复清单内旧程序文件，日志和恢复资料位于 `%LOCALAPPDATA%\Verjot\updates\update-*`；窗口显示具体原因及路径，可重新打开旧版。成功后清理本次安装包与备份文件，少量状态和日志保留。

0.11 包含的更新安全措施：每次安装尝试使用独立的 `rollback-*` 子目录；恢复前先验证整个备份，损坏或缺失时拒绝改动程序并保留资料。已校验成功的安装不会因清理文件被占用而回滚，窗口会提示未清理资料的位置。清理警告不等于安装失败；不要在未核实更新结果时删除失败尝试的恢复资料。

基础安装无需 Python、模型或新的更新运行时。只接受 `Qjzn/Verjot` 已发布（非草稿）的匹配 x64 EXE，要求 GitHub 的 SHA256 摘要；稳定版不接受预发行版，禁止降级。仅提交代码、CI 成功或上传草稿都不等于用户能收到安装更新。当前安装包未签名，摘要校验验证下载完整性，不替代发布者代码签名。

公开仓库可以匿名检查与下载。私有测试有两种本机授权方式：

- 在更新窗口勾选「使用已登录的 GitHub CLI」，本机需事先安装 `gh` 并执行 `gh auth login`，账号须可读取本仓库。该选项只用于本次窗口操作，不读取或导出 Token，不使用浏览器登录；CLI 不是公开版的基础依赖。
- 自行在 Windows 用户环境变量中设置 `VERJOT_GITHUB_TOKEN`，使用具有本私有仓库内容读取权限的 Token；值不填进配置、聊天、Issue 或日志。每次请求时读取，不要求重启；仅发送给 GitHub API，不随资产存储跳转转发。撤销在 GitHub 完成。后台自动检查私有仓库也需要此方式；不会后台调用已登录 CLI。

源码或便携目录不自动覆盖，须先使用安装包完成当前用户安装。更新目的目录固定为本机登记的该安装目录，不接受自定义远端更新源。

开机自启读写当前用户的 Startup 快捷方式，不增加配置字段、不要求管理员权限；只操作指向当前程序的入口，不修改其他安装的启动项。可在设置里启用或关闭。

先结束录音并等待后台转写，完成速记输入法选词后再保存设置。程序会保存并关闭便签、检查四个快捷键的占用情况，然后原子替换配置并立即切换。失败时保留原配置并恢复原快捷键；若其他程序在释放期间抢占旧键，会明确提示从托盘重启。设置窗口打开期间仍可用热键打开速记和开始录音，录音及后台转写进行中暂不能保存设置。

保存地址必须是已存在的普通完整目录，子文件夹仍使用相对路径；修改不迁移既有会议、速记或图片。窗口只保留当前打开时的配置快照，外部编辑冲突会拒绝保存或保留恢复副本；不能保证与不配合的外部编辑器跨进程事务。外部改配置后应关闭设置、重新打开，必要时重启程序。直接改配置文件仍按原有退出/重启流程操作。

缺少 API 密钥时，速记、设置和录音仍可使用；密钥在启动转写时校验，可以关闭“录音 + 转写”继续仅录音；旧本地配置只保留，不再自动连接。`--check-config` 和自检仍保持严格校验。版本说明与本地安装说明使用内置只读窗口，无需安装 Markdown 阅读器。正式版更新检查过滤预发布，测试版仍可检查后续测试版和正式版。

## 时间点回听

`Register-Playback.ps1 -Plan` 只查看计划，`Register-Playback.ps1` 为当前用户注册 `pianyan://`，`Register-Playback.ps1 -Unregister` 只移除本安装目录拥有的注册项；不覆盖其他程序或另一目录的协议。安装时可显式加 `-EnablePlaybackLinks`。不需要管理员权限，迁移程序目录后需先从原目录解除注册再在新目录注册。

新 Markdown 中的时间戳链接只携带本机会议编号和秒数，不包含音频绝对路径。接收端重新核对该场记录、保存范围、音频存在性与安全路径，再在原生播放器定位；不自动发声。协议不可用或阅读器不允许外部链接时，可在「最近会议 → 回听录音…」使用进度条和时间输入框。播放器不修改系统音量，旧会议与重命名后的同场记录仍以场次编号定位。

Verjot 从程序目录中的 `config.json` 读取配置。配置与 `ObsidianMeeting.exe`、`meeting_worker.py` 放在同一目录；它不从当前 PowerShell 目录、环境变量或其他位置寻找配置。

首次安装使用 `config.example.json` 创建配置；安装程序不会覆盖已有 `config.json`。可以由 AI 按本文填写和检查。日常路径与快捷键可从右键「设置…」修改，保存成功后立即生效；直接编辑配置文件前应先完成录音、等待转写结束并退出托盘程序，修改后重新启动，让录音程序与后台转写使用同一份配置。

## 普通文件夹与 Obsidian

`vault_root` 是输出根目录，也可以是普通文件夹，并不要求安装 Obsidian。该目录必须已经存在；首次安装时由安装程序创建。新会议保存在 `vault_root/meeting_folder/Verjot年月日时分/`，MP3 和转写 Markdown 同目录同名；同分钟加 `-02` 等序号。新安装 meeting_folder 为 Verjot，旧配置不改；已有会议、WAV 和旧附件目录不迁移。

- `open_in_obsidian: false`：生成普通 Markdown，录音使用相对于笔记的标准 Markdown 链接。转写完成后不自动打开 Obsidian 或其他应用，可以手动从托盘「最近会议」选择对应笔记或录音资料。
- `open_in_obsidian: true`：生成适合 Obsidian 的笔记与录音 Wiki 链接。`auto_open_completed_note` 也为 `true`，且当前没有录音时，才在完成后通过 `obsidian://` 自动打开笔记。需要已安装 Obsidian，且输出根目录是已登记的笔记库；`vault_id` 可填写其库 ID 或库名。录音中完成或启动时找回的成品从托盘手动打开。

为兼容旧配置，省略 `open_in_obsidian` 时默认是 `true`。新版 `config.example.json` 显式填写 `false`，便于先用普通文件夹完成安装与验证。

## 字段、默认值与约束

配置必须是一个 JSON 对象。所有字符串字段都必须使用字符串，不能用数字、布尔值、数组或 `null` 代替；可留空的字段应填写 `""`。未知字段会被拒绝，拼错字段名也会报错。

| 字段 | 类型 | 省略时的默认值 | 必填 | 约束与用途 |
| --- | --- | --- | --- | --- |
| `vault_root` | 字符串 | 无 | 是 | 已存在的绝对普通目录，不能使用相对路径或链接目录。普通文件夹模式与 Obsidian 模式都使用此字段。 |
| `vault_id` | 字符串 | `""` | 否 | Obsidian 库 ID 或库名。普通文件夹模式不使用。Obsidian 模式留空时先尝试 `vault_name`，再使用根目录的文件夹名称。 |
| `vault_name` | 字符串 | `""` | 否 | 兼容旧配置的库名字段。新配置优先填写 `vault_id`；普通文件夹模式可以留空。 |
| `meeting_folder` | 字符串 | `"会议记录"` | 否 | 根目录内的非空相对目录，可以使用安全的多级目录。禁止绝对或带根的路径、`.`、`..`、空路径段、Windows 非法字符和保留设备名。 |
| `quick_note_folder` | 字符串 | `"速记"` | 否 | 内置速记目录，路径约束同 `meeting_folder`；支持旧日期便签和新建独立便签，图片放在该目录的 `图片/`。 |
| `mic_device_id` | 字符串 | `""` | 否 | 留空跟随 `Capture / Console` 默认麦克风，包括录制中变更；填写完整设备 ID 时固定该输入。 |
| `system_device_id` | 字符串 | `""` | 否 | 非空固定该播放端点，优先于 `system_capture_mode`；留空按下面模式选择。名称不能代替 ID。 |
| `system_capture_mode` | 字符串 | `"all_active"` | 否 | `"all_active"` 录所有活动播放端点，覆盖应用分流；`"default"` 只跟随 `Render / Multimedia` 默认端点。固定 `system_device_id` 优先。 |
| `recording_protection_seconds` | 整数 | `5` | 否 | 误触保护，允许 `0`–`300` 秒，`0` 关闭。结束时有效录音不足此值则清理本场临时录音，不生成 MP3/Markdown、不转录；等于此值保留。暂停麦克风仍计时；旧版整场暂停资料仍按原规则读取。仅对新会议生效。 |
| `recording_segment_seconds` | 整数 | `300` | 否 | 每段无损原轨时长，10–600 秒；若先达到安全字节边界则提前切段。按连续帧切割，不重置设备或会议时间轴。仅对新会议生效。 |
| `mp3_bitrate_kbps` | 整数 | `192` | 否 | 结束录音后先生成的 MP3 固定码率，仅允许 128、192、256、320 kbps。API 转写使用校验后的 MP3；旧 WAV 成品不转换。仅对新会议生效。 |
| `asr_context` | 字符串 | `""` | 否 | 可选的识别术语提示，最多 2000 个字符。适合项目名、产品名、专有词；不是会议内容、历史对话或摘要指令。 |
| `asr_terms` | 字符串 | `""` | 否 | 已知术语清单，逗号、分号或换行分隔；最多 1000 字符、64 项，每项最多 64 字符。去重后与上下文合计不超过 2000 字符。 |
| `speaker_anchor_mode` | 字符串 | `"legacy"` | 否 | `legacy` 沿用旧声纹锚点；`clean` 从讲话中扣除同轨异组重叠区，选取最长 1.5～6 秒干净片段。候选功能，未默认开启。 |
| `asr_segmentation` | 字符串 | `"speaker"` | 否 | `speaker` 沿用按说话人切片；`speech` 按连续讲话切片，人物变化不会触发切片。多人段显示人物时间范围，文字未逐字对齐。候选功能，未默认开启。 |
| `asr_denoise` | 字符串 | `"light"` | 否 | 仅允许 `"light"` 或 `"off"`。`light` 对识别片段副本执行零相位 70 Hz 高通，减轻低频干扰；`off` 关闭。保存的会议录音不应用此处理，不保证对所有声音提高识别准确率。 |
| `asr_echo_filter` | 布尔值 | `true` | 否 | 对高置信、多个窗口支持且转写文字完全相同的延迟回声副本做转录去重。`false` 关闭。不会消除保存录音中的回声，也不会按文字相似度删除讲话。 |
| `hotkey` | 字符串 | `"Ctrl+Alt+L"` | 否 | 全局开始/结束录音快捷键。至少包含一个 `Ctrl`、`Alt`、`Shift`、`Win` 修饰键，最后一个键为 `A`–`Z`、`F1`–`F24` 或 `Space`。同一修饰键不能重复。 |
| `pause_hotkey` | 字符串 | `"Alt+Space"` | 否 | 仅暂停/继续麦克风，格式同 `hotkey`。仅在录音时注册，按一次暂停麦克风、再按一次恢复；电脑声音持续录制，会议计时不中断。与浮窗麦克风按钮共用状态。四个快捷键不能相同，已有自定义组合保留。 |
| `bookmark_hotkey` | 字符串 | `"Ctrl+Alt+K"` | 否 | 录音中标记重点时间，格式同 `hotkey`。仅在录音时注册，也可从托盘或浮窗右键标记。 |
| `quick_note_hotkey` | 字符串 | `"Ctrl+Alt+J"` | 否 | 展开/收起内置速记便签，格式同 `hotkey`；空闲、录音和转写期间均可使用，不改变录音状态。 |
| `silence_warning_seconds` | 整数 | `60` | 否 | 持续无声提醒的等待秒数，允许 `0`–`3600`，`0` 关闭。不能使用浮点数、字符串或布尔值。只在录音期间判断正在收录的实际峰值；暂停麦克风时仅检查电脑声音。 |
| `open_in_obsidian` | 布尔值 | `true` | 否 | 填写 `false` 使用普通 Markdown；填写 `true` 使用 Obsidian。自动打开还需满足下面字段及空闲条件。不能写成字符串 `"false"` 或 `"true"`。 |
| `show_processing_window` | 布尔值 | `true` | 否 | 结束后沿用 186×68 浮窗保留常用操作和等待动画，阶段和真实进度通过托盘查看，可收起。`false` 不自动显示会后浮窗，并在结束时收起已有窗；仍可从托盘主动展开，阶段刷新不会将手动展开的窗关闭。 |
| `animation_mode` | 字符串 | `"auto"` | 否 | 仅允许 `"auto"`、`"on"`、`"off"`。`auto` 跟随 Windows 客户区动画及高对比设置；`on` 只为 Verjot 开启动效，适合系统关闭动画但希望 Verjot 有动效；`off` 关闭非必要动画。均不修改 Windows 设置，不影响真实音量和处理进度。 |
| `notify_device_changes` | 布尔值 | `true` | 否 | 提醒设备变化；`false` 仅关闭提示，不关闭自动跟随、所有活动输出捕获、音量反馈或实际设备错误反馈。固定 ID 不随默认设备变化。 |
| `auto_open_completed_note` | 布尔值 | `true` | 否 | 仅在 `open_in_obsidian` 为 `true` 且当前没有录音时自动打开刚完成的笔记。`false` 始终手动打开。录音中完成的会议不会延迟到结束后突然打开；启动找回的成品也从托盘手动打开。 |
| `transcription_mode` | `api` / `local` | `api` | 否 | 桌面端统一显式配置音频转写 API；`local` 仅保留旧配置可读性，不启动内置模型。 |
| `auto_transcribe` | 布尔 | `false` | 否 | 默认仅录音；开启后，导出 MP3 再按配置转写。每场开始时固定；关闭后仍可手动转写。 |
| `api_base_url` | 字符串 | `""` | API 模式是 | OpenAI 兼容服务的完整 HTTP(S) 前缀，包含服务所需的版本路径。程序追加 `/audio/transcriptions`，不会猜测或补齐 `/v1`。 |
| `api_model` | 字符串 | `""` | API 模式是 | 服务实际支持的语音转写模型名，必须非空。不能用聊天模型名代替语音转写模型名。 |
| `api_key_env` | 字符串 | `"TINGJI_API_KEY"` | 否 | 存放 API 密钥的环境变量名称，不是密钥本身。API 模式要求启动进程能读取该变量中的非空密钥。 |
| `api_timeout_seconds` | 整数 | `120` | 否 | API 请求超时秒数，允许 `10`–`600`；不能使用浮点数、字符串或布尔值。 |

默认值指代码在字段省略时采用的值，不等同于示例文件中显式填写的值。三项反馈布尔字段缺省为 `true`；旧配置省略 `animation_mode` 时采用 `"auto"`，其他已确认字段不需要改动。Python 和录音程序读取同一份 `config.schema.json` 进行字段校验和默认值补齐。

保护时间内因故障自动停止，或保存、清理失败时，会保留尚存的临时资料并提示，不自动转录；正常主动结束的短录音仍按保护时间取消，非致命的设备启动告警不会单独阻止取消。

`meeting_folder` 可填写 `"会议记录"` 或 `"项目A/会议记录"`；不要填写 `"../会议记录"`、`"./会议记录"`、`"D:\\会议记录"`、`"项目A//会议记录"` 或 `"CON"`。`quick_note_folder` 使用相同的相对路径规则。

快捷键示例：`"Ctrl+Alt+L"`、`"Ctrl+Alt+K"`、`"Ctrl+Alt+J"`、`"Ctrl+Shift+F8"`、`"Win+F10"`、`"Alt+Space"`。须按示例大小写填写；`"L"` 缺少修饰键，`"Ctrl+Ctrl+L"` 重复修饰键，`"Ctrl+Alt+1"` 使用了不支持的普通数字键。`hotkey`、`pause_hotkey`、`bookmark_hotkey`、`quick_note_hotkey` 的实际组合必须两两不同，调换修饰键顺序也不能绕过冲突检查。合法组合仍可能被系统或其他程序占用：主快捷键注册失败会阻止启动并提示错误；暂停、重点或速记快捷键失败只提示对应键不可用，录音仍可使用。暂停与重点可从浮窗或托盘右键操作，速记可从托盘「速记便签」打开。提示会区分占用与其他 Windows 错误；需要更换组合时，退出程序、修改配置并重新启动。

默认 `Ctrl+Alt+L` 开始或结束整场录音；录音过程中按一次 `Alt+Space` 暂停麦克风，再按一次继续，电脑声音持续录制。浮窗麦克风按钮、右键「暂停麦克风 / 继续麦克风」与快捷键共用同一个状态，可以交替操作；不改变会议软件本身的麦克风静音设置。`pause_hotkey` 字段名与默认组合不变，原有自定义组合自动沿用。`Ctrl+Alt+K` 记录当前重点时刻，结束后进入 Markdown 的「重点时刻」。暂停与重点时刻快捷键在未录音时不由 Verjot 注册，系统和其他程序可以使用它们。

## 速记保存与恢复

纸贴标签及「更多便签」中的条目支持右键「删除便签…」，确认后将 Markdown 送入 Windows 回收站。当前输入先保存，成功后切换剩余便签；最后一篇被删除后显示未落盘的空白便签。附件不随之删除，恢复草稿、外部变更及保存/回收失败均会保留并说明。Windows 若提示不能回收而需永久删除，可取消保留。不增加配置字段，不操作剪贴板。

顶部为单行：新建「＋」、Logo 和当前文件名、置顶、最小化、关闭。正文内 `Ctrl+N` 新建独立 Markdown，空白未输入不落盘；关闭与 Esc 收起，最小化保留当前便签，可通过原快捷键恢复。再次打开恢复上次文件及各文件选区、滚动位置，跨天不强制切换；初次无历史状态时沿用当天日期文件。窗口调整大小仍用系统拖动，边缘可缩放。

速记最小化与会议控制共用同一个置顶浮窗。单击 Logo 展开，再次单击 Logo 或点击右上角关闭收起；鼠标移入、移出保持当前形态。所有展开状态固定为186×68逻辑像素，顶部只显示 Logo、名称 Verjot、关闭按钮，下方保留常用操作或录音控制。详细状态不以小字常驻显示，通过悬停 Logo/名称或托盘查看。

Logo 为24×24逻辑像素；展开后固定在面板左上角，名称居中间，右侧是关闭按钮。面板靠右/靠下时向内展开，Logo平滑移动到固定导航位置，收起时回到原胶囊锚点。拖动非按钮、非链接区域超过系统阈值可移动。贴边小条点击展开，悬停不改变形态。关闭只收起，录音和转写继续。

转写失败时，面板继续保留Logo、名称、关闭和三个常用入口，不常驻显示提示小字。完整原因通过悬停Logo/名称与托盘查看；可重试时，浮窗或托盘右键菜单提供「重试当前转写」。已有任务或不可重试时隐藏该命令，录制按钮始终开始新会议。

右下角文档菜单提供「鼠标移出自动收起导航栏」，默认勾选，沿用原有行为：鼠标移出后隐藏导航栏和标签，仅显示原位置的文本区域；移回正文即可恢复导航。取消勾选后，顶部和底部导航栏保持显示，标签仍按鼠标位置收起。选择立即生效并在重开后保留，无需改配置文件。导航显隐不拉伸正文、不重置阅读位置，输入法选区、滚动与图片位置保持不变。

鼠标进入正文区域显示左侧纸贴，按可用高度显示最多 5 个文件，其余从「更多」访问（最近 50 个）。当前和悬停标签略微伸出，过渡完成即停止动画计时器；离开窗口约 300 毫秒后收起。停留约 250 毫秒才请求后台只读预览，快速划过会取消过期结果。预览不改变原编辑器、保存目标、撤销记录或选区；移回正文恢复原文件，点击标签才切换。预览最多前 12,000 字符，图片按引用显示；正式打开时完整载入支持的图文。右下角文档菜单的「悬停标签预览内容」可关闭内容预览，标签与完整名称提示仍可使用。切换先保存当前输入，保存冲突时保持当前文件与恢复资料；图片正在插入或输入法选词时暂不切换。

顶部名称与操作图标使用同一垂直中心。鼠标离开窗口约 300 毫秒后隐藏上下工具栏和纸贴，仅保留正文；移回正文恢复，不移动正文、光标或滚动位置。操作工具栏时不会立即收起；上下文菜单、图片拖拽和保存失败提示可保持展开。标签完整名称在窗口外安全位置显示，原生弹窗若被屏幕边缘挤回正文则关闭提示；仍可从「更多」按完整名称搜索。

纸贴只放在窗口外侧：优先左侧，贴左屏时改到右侧；两侧都没有空间时隐藏纸贴，点击顶部文件名仍可切换。文件名保留拖动窗口功能，单击打开最近便签列表。「更多」列表支持文件名搜索、滚动、方向键选择、回车打开和 Esc 关闭；不读取文件正文来筛选。悬停展开通过只读覆盖层显示，不隐藏正在编辑的原生控件、不来回切换焦点；文字、输入法和编辑命令到达前先退出预览。鼠标移动也会补充恢复隐藏导航，不仅依赖进入事件，无永久轮询计时器。

图片：选中后四角拖拽锁定当前显示比例；左右边缘仅自由调整宽度，上下边缘仅调整高度。轮廓预览后松开应用；右键可适合窗口或按 1.25/0.8 倍缩放、恢复原图比例、查看原图，双击也可用系统查看器打开原始图片。只允许速记目录内通过既有路径与格式验证的本地图片，文件丢失时提示原因，不打开网络地址或任意程序。原生撤销/重做与自动保存继续生效。单宽度写为 `![图片|240](<相对路径>)`，自由尺寸为 `![图片|240x160](<相对路径>)`，wiki 图片相应保留 `![[路径|240x160]]`；原 PNG 不改写，不新增附件或全局快捷键。未缩放时保留原语法。尺寸参考逻辑像素，随屏幕 DPI 与编辑器缩放适配；边长最多 2000，极端长宽比超过 100:1 时保留引用，以免 Windows 图片导入失败。缩放沿用既有有界撤销缓存，达到上限时先保存、重开再调整。

图片拖拽期间按 Esc 只取消本次缩放，之后再按 Esc 才保存收起；滚动、编辑器缩放或重排导致坐标变化时取消旧拖拽，原尺寸不变。角点拖拽的轮廓与提交使用当前显示比例和同一尺寸上限；另行保留原始预览图片比例，供恢复原图比例时使用。

视图状态与预览偏好写入库外 `quick-note-files-<目录哈希>.json`，不同目录隔离，不写进笔记正文；旧窗口位置文件兼容保留。无需新增配置字段，现有快捷键不变。轻量滚动条只替换外观，继续使用原生滚轮和实际滚动范围，不轮询全文。

底部格式栏提供加粗、斜体、下划线、删除线、项目符号和插入图片。格式直接显示在原生编辑器中；先选中文字再点击可切换效果，未选中时作用于后续输入。快捷键分别为 Ctrl+B、Ctrl+I、Ctrl+U、Ctrl+Shift+X、Ctrl+Shift+L，仅在正文内生效。列表作用于选中行；仅有光标时保留光标位置，可接着输入。列表回车自动添加下一项，空列表项回车退出，Shift+Enter 仅换行。所有按钮悬停显示用途和快捷键，七个底栏图标随窗口宽度均匀分布。格式操作可整步撤销，字体修改及撤销/重做均自动保存。仍使用单份 Markdown：格式写为内联 HTML 的 b/i/u/s 标签，列表写为标准 `- `，不生成 RTF 附件。载入时支持这些标签及常用的加粗、斜体、删除线 Markdown；代码区间不解析，未闭合标记保留字面内容。未编辑文档原文不重写，修改后格式标签可能规范化。转换只在加载/保存时进行，每次键入不重新解析全文。插入图片沿用受限的本地文件路径，不读写剪贴板。


便签沿用 `vault_root`，新建与旧日期文档均保存在 `quick_note_folder/`，旧文件不迁移或改名。内容按 Markdown 原样保存；可粘贴截图，或粘贴/拖入可解码的本地图片文件，统一转为 PNG 存入同目录的 `图片/<内容哈希>.png`，正文使用相对引用。单个源文件及转换后 PNG 均不超过 12 MiB（12,582,912 字节），像素不超过 3600 万；多帧图片只取首帧。便签可显示速记目录内的 PNG、JPEG、GIF、BMP 本地引用，未能读取的引用保留原 Markdown。速记不依赖 Obsidian 是否开启，也不受会议成品自动打开设置影响。

默认 `Ctrl+Alt+J` 展开/收起，`Esc` 和关闭按钮也收起。首次打开才创建 Windows 原生 RichEdit 编辑器，不加载 WPF 或浏览器；初始尺寸 360×420 逻辑像素，默认置顶、可调整大小，窗口状态等本机设置保存在库外。编辑停顿 500 毫秒后由单个后台任务顺序保存，先将恢复草稿写入程序的 `work/quick-note/`，再保存正文；后续输入只保留最新待存快照。收起和退出等最新内容保存成功后续办，界面不等待磁盘刷写。保存策略无需新增配置，现有 `quick_note_folder`、`quick_note_hotkey` 继续有效。草稿不提交 Git，也不作为笔记附件。重新打开对应便签时，磁盘版本与草稿基准一致则恢复草稿；版本不一致则显示磁盘内容，并另外保留待合并草稿。更早日期的草稿可从该目录检查。只有用户主动粘贴时读取这一次剪贴板数据，不主动更改系统剪贴板。

图片编码与落盘使用同一后台队列；处理期间可继续输入，撤销会取消尚未插入的图片。完成时若正处于输入法组合，会等待选词结束再插入，并保留当前文字和光标；无需配置等待时间。最多排队 16 项，剪贴板图片的待处理像素总量不超过 3600 万；达到上限会提示稍后再试。标题栏使用系统拖动，遵循 Windows 的窗口拖动设置，不更改全局设置，也无需新增配置。

输入由 Windows 原生编辑器处理，不逐键遍历文档、编码图片或写入磁盘，也不接管输入法文本。普通 `Enter` 一次只插入一个换行，沿用笔记原有的 LF/CRLF 格式，无需增加换行配置。自动保存仍在停顿 500 毫秒后后台执行。原生编辑器替换不增加配置字段，`quick_note_hotkey`、`quick_note_folder` 及既有配置保持兼容。

图片预览使用固定容量，原图不缩小。图片过多或撤销预览缓存达到上限时，改用可编辑的 Markdown 图片引用显示，原图和保存内容仍保留。正文编辑上限为 4,194,304 个 UTF-16 单元；超出上限，或原文含 NUL、垂直制表符、字面对象替代字符 U+FFFC、孤立 CR 时，停止载入并保留原文件，可从文件夹使用其他编辑器处理。未知嵌入对象无法安全还原时停止保存、保留窗口，撤销该操作后重试；不能忽略提示或强杀程序。

外部更新或删除不静默覆盖笔记。点击底部提示可「打开速记文件夹」「复制当前内容」「打开草稿所在文件夹」，保存冲突时还可「保留草稿并载入磁盘版本」。右下角文档图标悬停可看完整路径，点击打开相同的保存与恢复菜单；正常输入与自动保存不再显示切换状态行，保存异常仍在底部明确提示。草稿按笔记的完整路径隔离，切换库或目录不会串用。草稿写入也失败时只保留窗口中的内容，应先复制保存，不能保证强制退出后的恢复。空闲、录音或转写期间请求退出，均先保存便签；保存失败或输入法组合尚未提交时保留编辑器并取消退出，录音不会先被停止。先处理提示，不要删除 `work/quick-note/` 来消除提示。原有 `Ctrl+Alt+L` 开始/结束录音、暂停及重点标记行为不变。旧独立 Obsidian 速记程序仍在运行时会争用默认组合，应先停用其进程与登录启动项，保留旧笔记及其他 QuickAdd 配置。

## 轻量反馈与会后任务

录音时浮窗左侧波形反映麦克风或电脑声音的实际输入，中间麦克风图标只控制并反馈麦克风；悬停查看实际设备名称和两路状态。正常录音不显示「录音中」文字；关闭麦克风显示划线图标，电脑声音仍被录制，波形仍可跳动。快捷键暂停麦克风时同样使用划线图标，左侧波形继续反映电脑声音；再次按下恢复麦克风。无明显输入表示当前安静，不能单凭安静判断设备失效；安静时不制造虚假音量跳动。

`silence_warning_seconds` 默认 `60`：正在收录的两路原始峰值持续低于 `0.003` 时提醒一次；持续安静不会反复刷屏，有输入恢复后才重新计时。关闭麦克风时不要求该路有声，仅依据仍在录制的电脑声音。`0` 关闭提醒。该阈值用于提示检查输入，不是语音识别的最低音量，也不能证明设备故障。

浮窗空白处或录音按钮的右键菜单与托盘共用操作入口，无需展开新面板。完成态两条路径仍保留自己的「复制完整路径」菜单。标记时记下从会议开始起的墙钟秒数，麦克风暂停期间计时持续，不移动重点时刻的位置；不会新增音频附件。

共享浮窗以约 250 毫秒的高阻尼曲线从 Logo 胶囊展开，收起更快；尺寸和圆角连续过渡，收起胶囊锚点与 Logo 尺寸固定，展开后 Logo 平滑进入居中品牌组，文字与按钮淡入后恢复原生交互。鼠标移入、移出不改变浮窗形态；快速点击 Logo 从当前形态反向，不重新播放整段动画。中途拖动会冻结当前形态，松手后从原尺寸继续过渡；贴边吸附也从松手位置衔接。跨屏拖动采用目标屏幕的缩放和位置，不套回旧屏幕锚点。只在过渡时缓存小块内容，结束或隐藏即释放，停稳后停止伸缩计时器，不引入额外运行依赖。计时器和曲线测试不等于真实高刷新率帧率认证。`animation_mode: "off"` 立即切换，`"auto"` 仍跟随系统设置。

波形随真实输入平滑变化，按钮状态采用约 120–180 毫秒的短过渡。`animation_mode: "auto"` 跟随 Windows 客户区动画设置，并在高对比模式下停用非必要动画；`"on"` 仅为 Verjot 开启动效，即使系统已关闭动画；`"off"` 停用非必要过渡和循环等待动画。所有模式都保留静态状态、真实音量和进度反馈，不修改 Windows 设置。

结束后浮窗沿用 186×68 尺寸保留品牌顶部和常用操作，不常驻显示处理小字，可收起，并用等待动画表示后台任务处理中。动画不表示录音输入或推算的完成比例；后台已经确定片段总数时显示真实完成段数，其他阶段显示阶段名称，不生成预计总百分比。托盘在浮窗收起时仍可查看状态。下一场录音优先显示当前录音，悬停可查看后台任务数量。

完成态使用两行实际路径：「录音：<相对路径>」「转录：<相对路径>」，不以「已完成」「已保存」占据保存位置。路径相对于 `vault_root`；长路径优先省略目录，文件名仍过长时省略其中间部分并保留扩展名，悬停显示完整绝对路径。点击对应行会在资源管理器选中该场录音或 Markdown，右键复制该文件的完整路径。托盘「最近会议」也提供分别定位两份文件的入口，始终绑定所选场次。点击定位和复制不会修改 `auto_open_completed_note` 的自动打开策略。

托盘「最近会议」用会议时间和状态标识记录，时间显示为 `MM-dd HH:mm:ss`，无法读取开始时间时使用会议目录名。命名后显示「时间 · 标题」。最多显示 20 场并优先包含需要关注的场次。每场分别提供「查看状态」「查看录音资料」，存在笔记时提供「打开转录笔记」，适合重试且有原始录音时提供「重试这场转写」，避免连续录制时误重试另一场。更早的本机资料可从 `work/` 查看。普通文件夹的笔记手动打开使用系统文件关联，无法打开时在资源管理器定位文件。重试先核对该场录制时保存的转写模式与服务设置，检查失败不会自动改为另一种模式或上传旧录音。

会后命名仅适用于转写完成且没有运行中 worker 的所选场次；有另一场正在录制时入口禁用。小输入框提交标题后，程序修改该场 Markdown 文件名与会议元数据，保持录音路径和音频内容；重名不覆盖。内部笔记管理路径一并更新，重试沿用命名。标题来自本场元数据，不是新增配置字段。

浮窗使用 186×68 逻辑像素，由 Windows 缩放到当前显示器；程序清单声明 Windows 10 兼容，配套 `ObsidianMeeting.exe.config` 为 .NET Framework 4.8 启用 `PerMonitorV2`。`Build.ps1` 自动生成对应的配置文件，更新或移动 EXE 时必须一并携带。高 DPI 支持不修改 Windows 缩放，也不需要增加 `dpi` 或字体配置字段。

## 启动恢复与本机资料

重启后检查 `work/` 中的会议元数据与处理状态。仍存活且进程身份匹配的转写任务会接回，不能只凭 PID 就重新启动或误接另一进程。工具退出期间完成的会议提供结果入口；适合重试且有原始录音的失败任务保留对应重试入口。需要关注的同一可读状态只提示一次；新一轮重试或状态变化可再次提示。JSON 或路径异常无法安全记录提示状态时，每次启动仍会提醒，不为消除提醒而覆盖异常资料。`show_processing_window: true` 时可通过原小窗查看；收起后状态刷新不会反复弹回。中断录音只提供状态与现有资料检查入口，不直接提供普通重试，也不自动开始录音、修文件头或上传。

`work/` 中的 `controller.json` 用于记录进程身份和提示状态，仅属于本机控制资料，不复制进笔记库，也不提交 Git。新会议的成品只有一条合并 MP3 与一份 Markdown。遇到中断先检查资料是否完整，再决定恢复步骤；不能把找到文件当作音频一定可恢复。

某场有正常完成状态、两条明确且安全的成品路径、保存根目录可访问，且没有采集、发布、校验或清理错误时，手动清理按剩余文件区分：两份都在为 `completed`；只保留 Markdown 为 `transcript_only`，显示「仅保留转录，录音文件已移除」；只保留录音为 `audio_only`，显示「仅保留录音，转录文件已移除」；两份都被移除为 `removed`，不列入最近会议。仅保留一份仍提供现有文件入口，不作为故障提醒、不自动重试；不会删除工作资料。异常或未完成任务、路径不明确、文件被同名目录替代和保存根目录不可用仍提示检查。把成品放回原处后会重新读取其状态。

旧版 `merged_audio.path` 只有 `meeting.wav` 这类文件名时，仅通过该场元数据中明确保存的绝对 `audio_output_dir` 还原完整路径，再执行相同的保存范围、扩展名和重解析点检查。包含子目录、上级目录、未知输出目录或越界路径的记录不猜测、不隐藏；已有明确的发布路径不会被此兼容规则替换。

新 Markdown 不输出录制时间、时长、引擎模板行、空「我的笔记」或 HTML 边界标记。正文范围和校验信息放在本机 `status.json` 的管理元数据中，重试保护正文之外的用户内容；检测到自动正文被用户改动时不会静默覆盖。旧边界标记仅在对应笔记安全重试时迁移，不批量清理用户历史笔记。说话人限制提示的删除以双方确认质量标准并通过验收为前提；标准提案与证据边界见 [质量说明](quality.md)。

## JSON 文件格式

- 使用 UTF-8 保存。JSON 不支持注释，不允许末尾多余逗号。
- Windows 路径中的反斜线必须写成 `\\`，例如实际路径 `D:\Meetings` 在 JSON 中是 `"D:\\Meetings"`。
- 字符串使用英文双引号；布尔值使用小写、不带引号的 `true` 或 `false`。
- 不要在配置中添加本文未列出的字段。

## 默认设备与固定设备

电脑声覆盖和固定设备按以下优先级选择：

- `system_device_id` 非空：只录指定输出，即使 `system_capture_mode` 为 `all_active` 也以固定 ID 为准。设备失效时保留错误，不偷偷换到别的端点。
- 输出 ID 留空、`system_capture_mode: "all_active"`：默认模式，在本场收录所有活动播放端点。不同应用分别走耳机、扬声器、显示器时不再只录其中一路；已有活动端点预先捕获，因此改默认输出无需先结束会议。会增加与活动端点数相应的临时磁盘与采集开销，不增加模型或浮窗控件。
- 输出 ID 留空、`system_capture_mode: "default"`：只跟随 `Render / Multimedia` 默认播放设备。应用被分配到非默认端点时不会被录下；这是显式缩小覆盖范围的选项。
- `mic_device_id` 留空：跟随 `Capture / Console` 默认麦克风；更换时沿用麦克风开关状态。固定 ID 时不跟随。上述角色均不是 Windows 的“默认通信设备”角色。

端点加入、移除和默认变化由采集层处理，提醒开关不决定是否跟随。新启用或重新连接的设备需要完成初始化；初始化前及设备真正中断期间的声音不能恢复，诊断会保留异常或生命周期信息。WASAPI 共享回环不能保证获取受保护或被独占的音频；“活动设备”也不保证用户能从它听见声音。请用短实录核对实际应用路由。

多端点覆盖会增加临时磁盘占用：例如 48 kHz、双声道、32 位浮点的每条原始轨约 1.38 GB/小时，5 条约 6.91 GB/小时；旧版路径额外的临时 RF64 双声道 PCM16 混音约 0.69 GB/小时，新版直接流式编码而不生成整场混音 WAV；最终 192 kbps MP3 约 86.4 MB/小时（均为十进制单位，忽略少量文件头，不含识别片段缓存）。处理中需同时预留原轨、MP3 和识别片段的空间；旧录音恢复路径还可能需要临时混音空间。原轨实际大小以设备格式为准，静音时间也占时间轴。正常成品验证成功后清理无损原轨和临时混音，采集异常则保留核查资料。只选择默认或固定输出可减少临时开销，但会缩小收录范围。

新录音使用原设备格式的无损 WAV 分段，默认 300 秒，按连续帧切分；单段另有低于 RIFF 上限的安全字节边界，先到者触发。各段共享原设备时钟校正及整场时间轴，前导静音、设备切换和麦克风暂停/继续仍保留正确位置。分段记录在 `sources[].segments`，每项包含受限文件名、`start_frame` 和 `frames`；处理时校验连续帧坐标和文件头，缺段、格式不同或损坏会明确失败，不静默跳过。

已有本地转写先把同一逻辑来源的无损段连续读取，再执行原有说话人分析和识别；交界不重置采样率转换相位，不经 MP3 解码。新版通过原生 NAudio + 动态 LAME 连续混音并直接编码，不生成整场 WAV；保留每轨捕获偏移、静音和暂停麦克风期间的时间。结束录音后先发布双声道 48 kHz CBR MP3，默认 192 kbps，再检查转写依赖。记录输入清单、原始分段 SHA256 与 MP3 SHA256；重试复用已校验的 MP3，文件被修改时拒绝覆盖。首次转写仍读取原始无损分轨。旧录音不迁移，恢复时继续原 RF64/FFmpeg 路径。MP3 完整解码帧数必须与无损混音相差不超过 1 采样，并核对逐帧码率和 SHA256，成功后才清理中间资料。

以下仅适用于旧录音的 FFmpeg 恢复路径。新版原生 LAME 使用其自身 Info 延迟/尾填充信息并校验总帧数，不执行这项补丁。本机 FFmpeg 7.1 实测存在极短尾块边界：输入长度除以 1152 余 1–46 采样时，生成的 Info/LAME 尾填充可能少记，解码会多出至余数 47。Verjot 仅对本次自行编码的文件，在核对原始输入长度、全部音频帧、已知 Info 布局、帧数和标签 CRC 后修正这一已复现差值，并重算标签 CRC；不修改音频负载。随后仍完整解码并执行原来的 1 采样门槛。未知布局、CRC 异常、截断或其他差值均失败并保留无损资料，不对已有 MP3 执行修复。

分段不降低录制时无损数据总量；转写目前仍按逻辑整轨处理，内存随会议时长和来源数量增长。不可继续的写入错误触发停止和收尾；磁盘完全写满时不能保证文件头或元数据落盘。旧 WAV 会议继续兼容，不自动转换或覆写。长会议与故障验证范围见 [隐患审查](risk-review.md)。

内部 `session.json.sources` 为本场设备轨清单，每项含 `source`、逻辑文件名 `path`、`kind`（`microphone` 或 `loopback`）及设备信息；首次麦克风/电脑轨的逻辑名仍为 `mic.wav`、`system.wav`，后续按 `_02` 等编号。新分段会议的逻辑文件本身不存在，实际文件以 `sources[].segments` 为准，例如 `mic.seg000001.wav`。各轨已按共同时间轴补入前导静音，`capture_offsets_ms` 为 0，不可再次添加设备启动偏移。没有 `sources` 的旧会议仍按原有两轨处理。声明的轨道或分段缺失会报错，不静默生成缺声的完整成品。

连续设备帧使用同一采样相位，内部以 2 秒窗口估计慢速时钟差，不按每包时间戳抖动反复插入静音。驱动明确报告间断、帧计数跳变、较大的时间缺口或异常校时斜率时保留诊断；不会用拉伸声音掩盖这些问题。未带异常标志、连续计数器的极短停顿仍可能与时间戳抖动无法区分，实际测试边界见 [质量说明](quality.md)。这些内部参数无需在安装配置中调整。

这些分轨只作本机处理中间数据，正常完成发布并校验后继续按原规则清理；用户最终得到一条合并 MP3 与一份 Markdown，不增加附件种类。采集已报告异常时，转写完成且成品齐全显示「转写完成 · 录音需检查」，成品缺失显示「采集异常 · 文件需检查」，保留原始轨及处理资料供核查，不把处理成功当作录音完整。仍可从最近会议打开成品；重新转写无法补回未采集的声音，不提供无效的普通重试。单纯存在诊断记录不自动升级为异常，以本场明确记录的异常状态或错误为准。

设备时间戳无效或采样位置回退时，使用带告警的估计路径；相邻包至少保留上一包的完整时长，避免兜底时间倒退而主动中断。估计不能证明真实时钟准确，仍保留时间不确定性的提示和核查资料；不把设备重连或转写成功视作漏音已补回。

程序的 `--list-devices` 入口可列出当前活动的输入与输出设备，并写入程序目录中的 `audio-devices.json`。选择麦克风应使用 `Capture` 设备 ID，选择电脑声音应使用 `Render` 设备 ID。安装和排障时可以让 AI 根据设备清单与默认设备诊断报告核对，配置文件中只保存所选 ID。

## 本地转写与 API 转写

历史开发工具曾通过 `transcription_mode: "local"` 使用本地模型。beta.23 桌面端已停用该连接和自动续转，下文依赖说明仅供独立研究复现，不能作为当前产品配置步骤。

`transcription_mode: "api"` 对 beta.11 新会议原生提交完整 MP3，无 Python 或说话人模型依赖。只有用户确认后才上传；处理、保留与收费由供应方决定，身份标签仅来自服务响应。旧会议保留历史 Python 分轨 API 工作流，仍需要原有依赖；不会自动改写、迁移或上传旧录音。

说话人目标已明确为跨两轨同一人统一、不同人分开。实现直接对两路可靠讲话片段的声纹做全局完整链接联合聚类，组内片段须彼此相符；不把原本的局部聚类整组强行合并。片段太短、重叠讲话或候选身份相似度差距不足时标为待确认。设备、噪声和串音仍可能导致误并或漏并，数字阈值不代表质量保证，验收仍需人工真值。

`asr_denoise: "light"` 只处理本地或 API 识别使用的片段副本，以零相位 70 Hz 高通减轻低频干扰；`"off"` 不执行该处理。不修改保存的会议录音，不重写原始录音，也不等于移除所有背景噪声。不同声音可能受益、无变化或变差，没有全面 CER 改善结论；对比时使用相同输入和人工真值，不能仅凭听感判定转写改善。

降噪设置作用于新会议；每场在开始时保存处理模式，已经开始或有识别缓存的会议重试保持原模式，不因修改配置而混用片段。旧缓存没有模式信息时按 `off` 解释，保留原有处理结果。

`asr_echo_filter` 是转录去重，不是录音回声消除：只比较麦克风与电脑声的 0–300 毫秒延迟候选，以短 FIR 拟合固定频响，并用不同窗口交叉检查，不能只凭模型输出相同文字删段。至少 1.5 秒、至少 3 个有效窗口、强波形一致、低残差、覆盖充分且不少于 8 个文字/数字字符逐字相同，才隐藏麦克风副本。短应答、文字不同、复述或证据不足仍保留；微弱同时发言可能与强回声混在一起，因此不能宣称具备声音分离能力。原始段、识别结果及录音保留至成品验证，录音中的回声不被此设置移除。

回声开关也按场冻结。旧的已准备缓存没有该字段时视作关闭，重试继续复用原片段和识别结果，不因升级而重新分析旧录音。`asr_context` 可明确提供已知姓名及品牌拼写，例如 `"本次会议术语：挚达，王晓彤。"`；提示不是校正真值，不保证未知姓名正确。

失败会议已有识别断点时，重试会在发布录音或写笔记前核对分段、片段身份、服务/模型及术语提示。修改 `asr_context`、API 服务/模型或内部片段后，不会把旧结果直接拼到新输入上；检查不兼容时保留原成品及断点并明确拒绝。需要沿用旧断点时先恢复原设置；需要换设置重做时使用独立录音目录，避免覆盖旧结果。已完成的场次不因重试重新识别。

API 使用 OpenAI 兼容的 `/audio/transcriptions` 接口。`api_base_url` 填写完整服务前缀，例如 `https://api.example.com/v1`，实际请求地址为 `https://api.example.com/v1/audio/transcriptions`；不要在前缀中重复填写该接口路径，也不能包含空白、地址内的账号密码、查询参数或片段。模型名以服务供应方实际支持的语音转写模型为准。

API 模式必须同时满足：服务前缀有效、模型名非空、`api_key_env` 指向的环境变量含有密钥。诊断会检查这些条件。配置文件只保存环境变量的名称，不保存密钥；不要添加 `api_key` 字段，也不要把密钥写进 `api_base_url`、`asr_context`、文档或诊断报告。

让运行 Verjot 的进程继承所需环境变量后再启动。修改环境变量后要重新启动 Verjot；仅在另一个 PowerShell 窗口设置变量，不会改变已经运行的 Verjot 进程。

模型下载由安装步骤完成，模型、虚拟环境与个人配置不应提交到源码仓库。无需为了填写配置把模型上传到 Git。

每场会议保存录制时的转写模式、模型与 API 服务前缀。尚未完成的场次重试时，若这些设置已改变，程序会保留录音与已有成品并提示恢复原配置，避免把原本选择本地处理的录音上传，或把录音发往另一服务。没有新导出清单的旧录音不从桌面端自动迁移或转写。更换模式或服务应在现有场次处理完成后进行；已经完成的成品不需要重新转写。

## 本地模式的 CPU、GPU 与识别设置

CPU 或 CUDA 后端由安装步骤选择并安装，不能通过新增 `backend`、`gpu` 等配置字段切换。模型与 Python 环境使用程序目录中的固定位置：`.venv/Scripts/python.exe` 与 `models/`，不支持用 `python_path`、`model_dir` 等配置键覆盖。

当前 `local` 仍使用 Qwen3-ASR-1.7B，已有说话人路径是 ONNX 分割、ERes2Net 与项目内匹配逻辑，不是完整 Community-1。FireRedASR2-AED 与完整 Community-1 在独立环境评估，未成为配置项或自动下载项。不要通过修改 `api_model`、替换既有模型目录，或增加 `asr_model`、`diarization_model` 等未实现字段来切换；评估不修改正式 `config.json`。安装边界、离线要求和结果见 [本地模型评估](local-model-evaluation.md)。

本地会议转写实际使用 ASR 的 `auto` 选择：CUDA 可用时优先使用 GPU，CUDA 不可用或遇到显存不足时可回退 CPU。CPU 转写通常更慢。安装 CUDA 后端本身不证明机器上的 CUDA 已可用，需以诊断和实际转写结果为准。API 模式的远端转写计算不受这项本地 ASR 选择控制。

`asr_engine.py` 独立命令行另有 `--device`、`--no-cpu-fallback` 和 `--max-new-tokens` 等参数；这些不是 `config.json` 字段。会议录音入口不会从配置传递这些参数，当前使用其默认值：`auto`、允许 CPU 回退、每段最多生成 512 个 token。识别语言为中文。

## 让 AI 运行配置与设备诊断

在程序目录运行以下命令，`--json` 输出供 AI 读取的 JSON 报告。不要使用 `ObsidianMeeting.exe --doctor`，诊断入口是 `tingji.py`。

```powershell
.\.venv\Scripts\python.exe tingji.py doctor --json
.\.venv\Scripts\python.exe tingji.py doctor --full --json
```

历史 Python doctor 的基础诊断检查严格配置与 schema、Python 3.12 x64、必要依赖的安装元数据、程序和 DLL、所需模型文件、目录写入能力及磁盘余量。目录写入检查只创建并删除自己的临时文件；磁盘余量不足会报告警告。API 模式检查服务前缀、模型名和密钥环境变量；只输出变量存在或缺失，不输出密钥值。

`--full` 进一步真正导入运行时依赖、检查本地 Torch/CUDA 可用性和 FFmpeg 的 `libmp3lame` 编码能力，并调用程序的设备诊断入口，从临时 JSON 报告核对默认麦克风、默认播放设备和配置设备是否活动可用。基础和完整诊断都不录音、不加载识别模型、不触发转写、不调用云 API、不联网，也不自动修改设置。

诊断通过代表报告中这些检查成功，不能替代一段已授权测试录音，也不能证明 API 服务接受了实际转写请求。AI 应保留未执行和警告项，不把它们当作已通过的证据。

## 配置出错时

需要音频完全不出本机时，使用默认仅录音，或由你自行部署不外发音频的本机 API，并明确填写其地址；桌面端不再启动内置 `local` 引擎。云端 API 会发送音频，不能因成品保存在本机而称为全程离线。现有 `api` 入口需要 `/audio/transcriptions`；不能仅把 `api_model` 改成 Qwen Omni 聊天模型就认为接入完成。

音频设备临时失败后，即使 Windows 未再发设备通知，也会在冷却后自动重试：首次 3 秒，连续打开失败按 6、12、24、48 秒退避，最多 60 秒；设备线程每约 2 秒巡检，所以实际重试会稍晚。成功打开后重置退避。重试新建来源并继续使用原会议时间轴，不覆盖失败前的轨道；缺口保留且提示采集异常，不能恢复当时未录到的声音。`notify_device_changes` 只控制通知，不关闭恢复机制；没有新增后台进程或需要调节的重试配置。

启动时先检查配置结构、字段类型、输出目录和快捷键，按错误提示修正后再启动。路径不存在、字段拼错、类型错误或快捷键格式错误，应在开始真实录音前处理。

有效的配置不能证明设备已可录音、Obsidian 已登记或 GPU 已可使用；安装完成后仍需检查设备诊断，并用一段明确授权的测试音频验证录音与转写。修改输出目录、子目录或打开模式前，应先等待现有转写完成，避免同一场录音前后使用不同配置。

## 识别候选与术语提示

本节字段仅在当前源码候选及其新构建的安装包中提供，已发布的 `v0.1.0-beta.2` 不支持；不要直接将这些字段写入旧版配置。安装候选也不代表真实会议识别准确率已验收。

不增加常驻服务、不下载额外模型、不改变录音浮窗。以下配置只影响之后开始的会议；修改后需通过设置保存或重新启动程序使配置生效。

本地 Qwen 在短句上可能把提示词当成正文。本轮已实际复现，因此不足 4 秒的片段不附加新的 `asr_terms`，保留原有 `asr_context`；不通过删改识别后的文字伪造正确结果。该保护不是准确率保证，长句仍需核验，API 模式也仍由供应方决定如何使用提示。术语默认留空，只填写少量确定存在的词，不粘贴整篇竞品转录或会议结论。

```json
{
  "speaker_anchor_mode": "clean",
  "asr_segmentation": "speech",
  "asr_terms": "挚达\nBOM\nOA",
  "asr_context": ""
}
```

这是需要合并进完整 `config.json` 的字段片段，不是可单独运行的配置。术语只填写已知拼写；为空则不附加术语。支持逗号、分号或换行分隔，去除重复项，但不会将未听清的声音强制替换成术语。普通上下文仍可通过 `asr_context` 提供，两者只作为 ASR 提示，不参与声纹分组。新录音会冻结这两个值及锚点、切片模式；旧会议保持原有缓存和断点，不会因升级或改配置而自动重识别。对旧成品换设置做对比必须另建隔离目录。

`clean` 只在原讲话时间范围内扣除同轨其他局部分组的重叠区，再选择最长的干净区间作为声纹锚点；不同音轨不会互相排除，不借设备编号认人，不固定会议人数，不放宽原聚类阈值。该方法依赖前级分段，不能保证局部分组本身正确；当前保持 `legacy` 默认，等待人工身份标注验收。

`speech` 合并同一来源相邻/重叠的讲话区间，再按静音边界切成不超过24秒的核心片段，保留首尾少量上下文；麦克风和每个电脑声来源仍分开识别。切片不随局部人物编号变化，人物时间线保留在处理中间资料 `speaker_turns.json` 及片段的 `speaker_spans` 中。确认同一人物覆盖整段时显示单人；有多个人物时正文显示“本段多人”和说话时间，不声称每个字已准确归属某人。没有加入额外的字级对齐模型。当前保持 `speaker` 默认；片段减少或待确认减少均不是识别质量通过证据。

成功处理后，两种模式都按原策略清理中间资料，只向用户保留一条 MP3 和一份 Markdown；录音异常、处理中断或成品校验失败仍保留恢复资料。候选先用副本对比，不覆盖已有录音、正文、命名或人工修订。具体质量边界见 [质量说明](quality.md)。

新构建的源码候选会在“说话人待确认”后注明具体原因，例如发言过短、多人重叠、与多个说话人相似、有效声纹不可用或处理失败。无需增加配置字段，不改变聚类阈值、默认模型或人物归属。原因来自实际处理步骤；旧会议没有原因数据时只显示“尚无足够的身份判定证据”，不会自动重写旧文件。声纹处理失败可重试；发言过短或声音相似则不保证重试后能确认。转写分段包含多人时，原因保留在各说话时间范围内，不把整段正文强行归给一个人。

段内双视图和原始麦克风纠正仍是独立研究候选，不提供正式配置开关、不随基础安装加载。麦克风来源本身不等于本人，只有通过声学证据和独立对照才能考虑替换；本轮没有通过人物质量验收。详见[本地模型评估](local-model-evaluation.md)。

## 在设置里录入快捷键

常规页点击对应快捷键，直接按 Ctrl / Alt / Shift / Win 与字母、F1–F24 或空格的组合，松开主键完成。Esc、点击别处或关闭设置会取消本次未完成录入；原组合仍保留。录入只修改窗口里的候选值，点击保存才生效。重复的组合会就地提示；系统或其他软件占用的组合在保存时说明原因，并保留旧配置。Windows 保留组合可能由系统优先处理，建议使用 Ctrl+Alt 或 Ctrl+Shift 组合。

录入期间只暂停 Verjot 自己的快捷键绑定，不使用全局键盘钩子，不读取剪贴板。松键、取消或关闭后恢复当前已保存的绑定；请在录音和转写结束后配置。

## 浮窗操作（beta.23）

单击 Logo 或贴边小条展开，再次单击 Logo 收起；鼠标移入、移出保持当前形态。待机、录制、处理中和失败状态均可点击侧边垂直居中的箭头收起。贴边也不因移出自动折叠，手动收起才变为小条。失败时三个常用图标仍为速记、录制、设置；右键「重试当前转写」重试，不能重试时不显示链接。链接区域不参与拖动。


### 界面中的本机配置检查

设置 → 转写先选择“仅录音”或“录音＋转写”。后者显示 API 地址、模型名称与 Windows 密钥变量名；超时、术语和上下文在高级选项中。检查配置只读取字段和本机密钥变量的存在状态，不联网、不上传音频、不写配置；缺失原因在页面内显示。检查有效不等于服务连通、模型支持语音或实际转写成功。密钥值不会显示在检查结果中，真正提交仍保留目标确认。旧降噪与回声配置值保留，但本页不再展示对 API 无效的调节项。
