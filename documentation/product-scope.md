# 听记第一版范围

听记面向需要保存中文会议录音与转录的 Windows 用户。新人由 AI 完成安装和配置，日常通过快捷键、浮窗与托盘完成记录；成品可以保存到普通文件夹，也可以进入 Obsidian 笔记库。

## 第一版三项功能

| 功能 | 用户可完成的事 | 结果与约束 |
| --- | --- | --- |
| 录下会议 | 录制麦克风与电脑声音，开始/结束、整场暂停/继续、单独关闭麦克风、收起浮窗、标记重点时间。 | 默认 `Ctrl+Alt+L` 开始/结束，`Alt+Space` 暂停/继续，`Ctrl+Alt+K` 标记重点。三组均可配置且不能冲突，暂停与标记仅在录音时注册。整场暂停同时影响两轨；关闭麦克风时电脑声音仍录制。 |
| 得到中文转录 | 结束后在后台进行说话人分组与中文转写；选择本地 CPU/CUDA 或音频转写 API。 | 本地模式使用已下载模型；API 模式仍在本地分组说话人，把讲话片段上传到配置的服务。识别结果需要结合录音核对。 |
| 保存并恢复记录 | 得到一条合并 WAV 与一份 Markdown 转录；从托盘按时间打开对应笔记、查看录音资料、会后命名或重试失败会议。 | 验证成功后清理程序工作区的生成临时文件；失败保留恢复资料。内部元数据管理自动正文范围，保留范围外手写内容；范围内已被用户修改时不静默覆盖。 |

普通文件夹无需安装 Obsidian，默认不自动打开应用。使用 Obsidian 时需要已经登记的笔记库；这是用户选择的输出方式，安装过程不建立新的设置界面。

## 日常体验

| 改进 | 已提供的行为 | 边界 |
| --- | --- | --- |
| 会后处理与按场重试 | 结束后沿用 186×68 浮窗，以等待动画配合阶段或真实片段数，可收起。完成后两行展示实际录音、转录相对路径；悬停完整绝对路径，点击定位文件，右键复制路径。托盘按场次提供状态、两份成品定位和适用的重试。新录音优先显示。 | 等待动画只表示后台处理中，不表示音频输入或未知阶段的总百分比。长路径优先省略目录，文件名仍过长时省略其中间部分并保留扩展名，可查看完整位置。后台完成时若正在录音不切换前台；只有启用 Obsidian、允许自动打开且空闲才自动打开刚完成的笔记。 |
| 录音与麦克风反馈 | 左侧波形随麦克风或电脑声音的实际输入跳动，中间图标只控制并反馈麦克风；悬停分别查看两路设备名和状态。默认设备改变可提醒。 | 正常录音不显示「录音中」文字。关闭麦克风用划线图标表示，电脑声音继续；整场暂停才停止波形并在左侧显示「已暂停」。安静不制造虚假音量跳动。当前设备不自动迁移，固定设备 ID 不随默认选择变化提醒。 |
| 启动恢复提示 | 扫描本机工作资料，按进程身份接回仍在运行的转写；显示退出期间完成的结果、适用的失败重试与中断录音检查入口。同一可读状态只提示一次，重试或状态变化后可再提示。 | 中断录音不直接提供普通重试，资料需要检查后才判断可恢复程度；不自动修 WAV 文件头、继续录音、上传旧音频或删除原资料。JSON 或路径异常不能安全记录提示时，每次启动仍会提醒。 |
| 重点、命名与输入提醒 | 录音中可从快捷键、托盘或浮窗右键标记重点；成品列出会议时间轴上的重点时刻。空闲时可用小输入框命名已完成会议。两路持续无声默认满 60 秒提醒一次。 | 重点按墙钟时间记录，包含整场暂停。命名只改 MD 文件名和会议元数据，WAV 不变，重名不覆盖；正在录音或该场仍在转写时不可命名。无声提醒有声后重计时，整场暂停不提醒；关闭麦克风时只依据电脑声判断。 |
| 轻量右键与清晰显示 | 浮窗空白处及录音按钮右键共用托盘操作，结果路径保留复制完整路径。浮窗按系统 DPI 缩放，菜单使用原生文字绘制。 | 尺寸仍为 186×68 逻辑像素。使用 Windows 10 兼容清单与 .NET Framework 4.8 `PerMonitorV2`，更新须携带同名 `.exe.config`；不改变 Windows 缩放或增加设置界面。 |
| 手动清理历史 | 正常完成后只删 WAV 显示「仅保留转录」，只删 Markdown 显示「仅保留录音」，保留现有文件入口，不作故障提醒、不自动重试；两份都删除后不再列入最近会议。 | 必须有明确安全的成品路径、可访问的保存根目录且没有采集、发布、校验或清理错误。异常或未完成记录、路径不明、同名目录替代文件及保存根目录不可用仍提示检查；不自动删除内部工作资料，不自动重建成品。旧版相对音频文件名仅结合该场明确保存的绝对输出目录解析，继续执行路径安全校验。 |

三个配置字段 `show_processing_window`、`notify_device_changes`、`auto_open_completed_note` 均为布尔值并默认 `true`。旧配置省略 `animation_mode` 时使用 `"auto"`，其他已确认字段保留原值。关闭 `show_processing_window` 只关闭自动展开：结束时收起已有窗，仍可从托盘手动展开查看。「最近会议」以秒级时间标识各场，最多显示 20 场，优先包含需要关注的记录；更早的本机资料可从 `work/` 查看。内部 `controller.json` 只记录本机控制身份与提示状态，不增加笔记库附件。

输入波形平滑变化，按钮使用约 120–180 毫秒短过渡。`animation_mode: "auto"` 跟随 Windows 客户区动画及高对比设置；`"on"` 只为听记开启动效，适合系统关闭动画但希望听记有动效的情况；`"off"` 关闭非必要动画。均不修改 Windows 设置，停用动效时仍保留静态等待状态、真实输入和进度反馈。成品依旧只有一条 WAV 和一份 Markdown。

`bookmark_hotkey` 默认 `"Ctrl+Alt+K"`；`silence_warning_seconds` 默认整数 `60`，允许 `0`–`3600`，`0` 关闭。无声判定使用正在录制的输入峰值持续低于 `0.003`，是检查输入的提醒，不是设备故障判定或转写质量结论。

新 Markdown 去掉录制时间、时长、引擎模板行、空「我的笔记」与 HTML 管理标记，保留录音入口、转录、适用的重点与暂停区间。旧标记在安全重试时迁移，不批量重写历史笔记。有关说话人分组的限制说明暂时保留；移除前须确认质量标准并取得相应证据。

## 使用边界

转写发生在录音结束后的后台处理阶段。第一版不提供实时字幕、自动会议摘要、行动项提取、说话人真实姓名识别或云端原生说话人分析。

说话人需求已明确：同一人在麦克风与电脑声音两轨上统一编号，不同人分开。实现直接比较两路可靠讲话片段的声纹，进行要求组内片段彼此相符的全局完整链接联合聚类，避免把局部编号整组强行合并。短段、重叠或身份区分不足显示「说话人待确认」，不强行归并。设备声道、串音、多人重叠和噪声仍可能造成误并、漏并或文字错误，不能保证全部归属正确。`asr_context` 可以提示项目名和术语，但不能保证姓名或专有词识别正确。

`asr_denoise` 默认 `"light"`，仅对识别片段副本执行零相位 70 Hz 高通；`"off"` 可关闭，保留 WAV 始终不改。该处理只针对低频干扰，不等于全面背景降噪，也没有广泛中文 CER 改善证据。

多次输出一致只说明重复稳定，不等于说话人归属或识别文字正确。当前合成混音和官方多人样本的客观测试，尚不能代替带人工真值的实际双路中文会议验收。用户要求的跨轨身份一致、完整录音和高质量正文仍需实际会议逐项验证，指标提案和已有证据见 [质量标准与证据](quality.md)；当前不能宣称高质量已达标。

API 模式要求供应方支持音频转写端点，不能把可聊天的服务直接当作可转写的服务。上传的音频片段如何保存和使用，遵循用户选定供应方的政策。安装和 doctor 不上传音频；首次真实上传测试由用户明确同意。

AI 负责按用户选择填写配置、安装依赖、解释自检结果与协助恢复。默认不设置登录自动启动、不启动录音、不改变全局 Python，也不覆盖已有配置或中断用户的录音。API 密钥只从环境变量读取，不进入配置和仓库。

## 后续小范围候选

可在真实使用反馈后考虑常用术语清单和可选 Markdown 会议模板。优先由 AI 整理已有配置与笔记文件，保持日常记录操作简短；这些建议不代表当前已有自动摘要或新的大模型交互界面。

验收应分别记录环境自检、真实录音与所选转写链路。doctor 通过不代表新机器上的 CPU 模型推理、GPU 推理或真实 API 转写已通过。安装步骤见 [AI 代安装说明](ai-install.md)，字段与默认设备行为见 [配置说明](configuration.md)。
