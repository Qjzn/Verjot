# verbit 第一版范围

> 当前 beta.38：新用户默认仅录音，无推荐模型下载；速记、原生 MP3 导出与可选 API 均无需 Python 或模型。API 提交完整 MP3，身份信息仅来自服务返回；旧模型与配置文件保留，但桌面端不探测或自动连接，历史 Python 流程仅供研究。会议按 `verbit年月日时分/同名.mp3` 保存，API 成功后生成同名 Markdown。实际配置见[安装说明](install-windows.md)。


verbit 面向需要保存中文会议录音与转录的 Windows 用户。新人由 AI 完成安装和配置，日常通过快捷键、浮窗与托盘完成记录；成品可以保存到普通文件夹，也可以进入 Obsidian 笔记库。

## 第一版四项功能

| 功能 | 用户可完成的事 | 结果与约束 |
| --- | --- | --- |
| 录下会议 | 录制麦克风与电脑声音，开始/结束、暂停/继续麦克风、收起浮窗、标记重点时间。 | 默认 `Ctrl+Alt+L` 开始/结束，`Alt+Space` 暂停/继续麦克风，`Ctrl+Alt+K` 标记重点。三组均可配置且与速记键不能冲突，暂停与标记仅在录音时注册。快捷键、浮窗麦克风按钮与右键菜单共用状态；电脑声音持续录制。 |
| 得到中文转录 | 默认仅录音，按需选择第三方音频转写 API；已有本地模式兼容。 | 新 API 原生上传校验后的完整 MP3，不依赖本地模型；文字与身份由供应方返回。未配置或取消上传时保留本地录音。识别结果需回听核对。 |
| 保存并恢复记录 | 得到一条合并 MP3 与一份 Markdown 转录；从托盘按时间打开对应笔记、查看录音资料、会后命名或重试失败会议。 | 默认 192 kbps，录制与识别使用无损音轨，旧 WAV 会议保持原样。正常验证成功后清理程序工作区的生成临时文件；失败或已报告采集异常时保留恢复资料。采集异常与转写完成分开表示，已完成的转写不提供无法补回漏音的重复识别入口。内部元数据管理自动正文范围，保留范围外手写内容；范围内已被用户修改时不静默覆盖。 |
| 随手速记 | `Ctrl+Alt+J` 或托盘展开/收起内置便签，默认置顶、360×420 逻辑像素且可调；恢复上次文件，左上角「＋」新建，纸贴标签切换最近文件，支持延迟只读预览；可粘贴截图或粘贴/拖入本地图片。 | 沿用保存根目录，初次沿用日期文件，新建独立 Markdown；空白不落盘。图片转为 PNG 并用相对引用，单个源文件及转换后 PNG 不超过 12 MiB、3600 万像素，多帧取首帧。停顿 500 毫秒及收起、切换前保存，库外保留恢复草稿和各文件视图；外部变化不覆盖，保存失败保留编辑器并阻止退出。不依赖 Obsidian，不改变原录音操作。 |

普通文件夹无需安装 Obsidian，默认不自动打开应用。使用 Obsidian 时需要已经登记的笔记库；这是用户选择的输出方式。安装与模型配置可由 AI 完成，日常路径和快捷键通过右键「设置…」修改。

## 日常体验

| 改进 | 已提供的行为 | 边界 |
| --- | --- | --- |
| 会后处理与按场重试 | 结束后沿用 186×68 浮窗，以等待动画配合阶段或真实片段数，可收起。完成后两行展示实际录音、转录相对路径；悬停完整绝对路径，点击定位文件，右键复制路径。托盘按场次提供状态、两份成品定位和适用的重试。新录音优先显示。 | 等待动画只表示后台处理中，不表示音频输入或未知阶段的总百分比。长路径优先省略目录，文件名仍过长时省略其中间部分并保留扩展名，可查看完整位置。后台完成时若正在录音不切换前台；只有启用 Obsidian、允许自动打开且空闲才自动打开刚完成的笔记。 |
| 录音与麦克风反馈 | 左侧波形随麦克风或电脑声音的实际输入跳动，中间图标只控制并反馈麦克风；悬停查看设备名和状态。默认覆盖全部活跃播放端点，默认麦克风变化会跟随。 | 正常录音不显示「录音中」文字。关闭麦克风后电脑声音继续；快捷键暂停麦克风时也保留电脑声音波形，会议计时持续。安静不制造虚假输入。`system_capture_mode: "default"` 可只跟随默认输出；固定 ID 锁定指定设备。新设备初始化仍可能短暂缺音，诊断保留；不承诺无缝热切换。 |
| 启动恢复提示 | 扫描本机工作资料，按进程身份接回仍在运行的转写；显示退出期间完成的结果、适用的失败重试与中断录音检查入口。同一可读状态只提示一次，重试或状态变化后可再提示。 | 中断录音不直接提供普通重试，资料需要检查后才判断可恢复程度；不自动修 WAV 文件头、继续录音、上传旧音频或删除原资料。JSON 或路径异常不能安全记录提示时，每次启动仍会提醒。 |
| 重点、命名与输入提醒 | 录音中可从快捷键、托盘或浮窗右键标记重点；成品列出会议时间轴上的重点时刻。空闲时可用小输入框命名已完成会议。两路持续无声默认满 60 秒提醒一次。 | 重点按墙钟时间记录，包含麦克风暂停期间。命名只改 MD 文件名和会议元数据，录音不变，重名不覆盖；正在录音或该场仍在转写时不可命名。无声提醒有声后重计时；关闭麦克风时只依据电脑声判断。 |
| 轻量右键与清晰显示 | 浮窗空白处及录音按钮右键共用托盘操作，结果路径保留复制完整路径。顶部左侧返回，中间品牌，右侧关闭浮窗；右键提供设置。浮窗按系统 DPI 缩放，菜单使用原生文字绘制。 | 尺寸仍为 186×68 逻辑像素。关闭只隐藏浮窗；录音时禁用返回。设置仅在空闲、速记已安全保存时应用，冲突不覆盖。使用 .NET Framework 4.8 `PerMonitorV2`，更新须携带同名 `.exe.config`，不改变 Windows 缩放。 |
| 时间点回听 | 新转录与重点时间可使用本机 `pianyan://` 定位，最近会议也提供独立播放器入口。 | 协议需显式注册；播放器先暂停，用户点击播放才发声。MP3 定位有编码器与解码器误差，旧笔记不批量修改。 |
| 首次实际验收 | `tingji.py verify` 在隔离目录复用生产采集、编码与可选转写流程，输出明确报告和文件位置。 | 计划模式无副作用；录音、播放、云上传分别需要同意。信号存在及结构检查不能代替人工回听、时间线和说话人质量验收。 |
| 手动清理历史 | 正常完成后只删录音显示「仅保留转录」，只删 Markdown 显示「仅保留录音」，保留现有文件入口，不作故障提醒、不自动重试；两份都删除后不再列入最近会议。 | 必须有明确安全的成品路径、可访问的保存根目录且没有采集、发布、校验或清理错误。异常或未完成记录、路径不明、同名目录替代文件及保存根目录不可用仍提示检查；不自动删除内部工作资料，不自动重建成品。旧版相对音频文件名仅结合该场明确保存的绝对输出目录解析，继续执行路径安全校验。 |

三个配置字段 `show_processing_window`、`notify_device_changes`、`auto_open_completed_note` 均为布尔值并默认 `true`。旧配置省略 `animation_mode` 时使用 `"auto"`，其他已确认字段保留原值。关闭 `show_processing_window` 只关闭自动展开：结束时收起已有窗，仍可从托盘手动展开查看。「最近会议」以秒级时间标识各场，最多显示 20 场，优先包含需要关注的记录；更早的本机资料可从 `work/` 查看。内部 `controller.json` 只记录本机控制身份与提示状态，不增加笔记库附件。

输入波形平滑变化，按钮使用约 120–180 毫秒短过渡。`animation_mode: "auto"` 跟随 Windows 客户区动画及高对比设置；`"on"` 只为 verbit 开启动效，适合系统关闭动画但希望 verbit 有动效的情况；`"off"` 关闭非必要动画。均不修改 Windows 设置，停用动效时仍保留静态等待状态、真实输入和进度反馈。新会议的成品只有一条 MP3 和一份 Markdown。

`bookmark_hotkey` 默认 `"Ctrl+Alt+K"`；`silence_warning_seconds` 默认整数 `60`，允许 `0`–`3600`，`0` 关闭。无声判定使用正在录制的输入峰值持续低于 `0.003`，是检查输入的提醒，不是设备故障判定或转写质量结论。

新 Markdown 去掉录制时间、时长、引擎模板行、空「我的笔记」与 HTML 管理标记，保留录音入口、转录、适用的重点与暂停区间。旧标记在安全重试时迁移，不批量重写历史笔记。有关说话人分组的限制说明暂时保留；移除前须确认质量标准并取得相应证据。

## 使用边界

转写发生在录音结束后的后台处理阶段。第一版不提供实时字幕、自动会议摘要、行动项提取或真实姓名识别。新 API 只展示供应方实际返回的身份分组，不自行生成全局身份。

已有本地兼容路径的说话人需求：同一人在麦克风与电脑声音两轨上统一编号，不同人分开。实现直接比较两路可靠讲话片段的声纹，进行要求组内片段彼此相符的全局完整链接联合聚类，避免把局部编号整组强行合并。短段、重叠或身份区分不足显示「说话人待确认」，不强行归并。设备声道、串音、多人重叠和噪声仍可能造成误并、漏并或文字错误，不能保证全部归属正确。`asr_context` 可以提示项目名和术语，但不能保证姓名或专有词识别正确。

`asr_denoise` 默认 `"light"`，仅对识别片段副本执行零相位 70 Hz 高通；`"off"` 可关闭，保留的会议录音不应用这项处理。该处理只针对低频干扰，不等于全面背景降噪，也没有广泛中文 CER 改善证据。

多次输出一致只说明重复稳定，不等于说话人归属或识别文字正确。当前合成混音和官方多人样本的客观测试，尚不能代替带人工真值的实际双路中文会议验收。用户要求的跨轨身份一致、完整录音和高质量正文仍需实际会议逐项验证，指标提案和已有证据见 [质量标准与证据](quality.md)；当前不能宣称高质量已达标。

API 模式要求供应方支持音频转写端点，不能把可聊天的服务直接当作可转写的服务。上传的完整 MP3（旧兼容链为片段）如何保存和使用，遵循用户选定供应方的政策。安装和 doctor 不上传音频；首次真实上传测试由用户明确同意。

AI 负责按用户选择填写配置、安装依赖、解释自检结果与协助恢复。默认不设置登录自动启动、不启动录音、不改变全局 Python，也不覆盖已有配置或中断用户的录音。API 密钥只从环境变量读取，不进入配置和仓库。

## 后续小范围候选

可在真实使用反馈后考虑常用术语清单和可选 Markdown 会议模板。优先由 AI 整理已有配置与笔记文件，保持日常记录操作简短；这些建议不代表当前已有自动摘要或新的大模型交互界面。

验收应分别记录环境自检、真实录音与所选转写链路。doctor 通过不代表新机器上的 CPU 模型推理、GPU 推理或真实 API 转写已通过。安装步骤见 [AI 代安装说明](ai-install.md)，字段与默认设备行为见 [配置说明](configuration.md)。
