# 项目隐患审查与验证计划

审查日期：2026-10-15。基线为 `17b6d13`。范围包括录音写入与设备生命周期、成品发布和清理、旧记录迁移、转写准备、API、配置、安装与恢复。以下区分已经复现的问题和仍需验证的边界；短测试、代码检查和尺寸估算不能替代真实长会议验收。

## 已复现并修复

| 问题 | 旧行为的实际证据 | 修复与验证 |
| --- | --- | --- |
| 成品被替换后仍清理原轨 | 把已发布录音替换成同尺寸、同帧数的合法 WAV，旧 worker 返回 0 并删除原轨与识别结果。 | 保存成品内容 SHA256，清理前核对内容；不匹配时保留原轨和结果。新增测试先失败，修复后通过。哈希按 1 MiB 分块计算，不整场加载。 |
| 覆盖未归属本场的已有录音 | 首次发布目标已有合法 WAV，旧 worker 实际替换其内容。 | 已有目标必须同时匹配本场发布记录、路径、大小和内容；处理阶段更新保留发布记录，识别失败后可安全重试。 |
| 异常收尾和设备更换后的资源释放 | 注入尾包写入失败时 writer 未关闭；停止线程超时后再次 Dispose 不再清理；已结束端点的等待句柄留到整场结束。 | 异常收尾仍释放写入器，超时后的清理允许重试，结束端点及时释放资源；通过不打开设备的生产类故障注入验证。 |
| 写盘或 WAV 容量失败后仍继续计时 | 使用虚拟长度流触发当前 NAudio 的真实 RIFF 护栏，不创建 4 GB 文件；旧会话仅记录错误，传入的失败回调没有被使用。 | 不可继续的写入错误通知控制器停止并收尾；普通单一端点异常继续保留其他来源。回调按场次关联，防止旧故障影响新会议。不把该保护称为长会议格式升级。 |
| 旧记录迁移覆盖文件或中途失败 | 在隔离旧会话中观察到已有 `meeting.wav` 被替换；去掉旧 HTML 标记后，迁移工具仍要求标记存在而抛错。 | 有现存录音时停止而不覆盖；新合并记录保存内容校验和正文管理信息，迁移与整理支持无 HTML 标记，保留手写内容。新增完整准备→整理测试及替换文件拒绝测试。 |
| 旧会议命名和普通提交失败后无法恢复 | 已改名记录迁移时丢失 `note_filename`；注入状态写入失败后，笔记已变更而状态未更新。 | 保留标题、文件名、链接方式、重点和暂停信息；提交前发生普通异常时，仅在笔记仍为本次生成字节时原子恢复旧笔记。已校验的合并 WAV 可直接复用，不重写；用户并发编辑和提交后的异常不触发单独笔记回滚。 |
| 模型续传可能拼接错误字节 | 旧下载函数把 4 字节断点与错误起点的 206 响应拼为预期 10 字节并发布。 | 校验 Content-Range 起止与总量、内容编码和响应边界；验证正常续传、200 重启、截断后恢复。使用伪传输，无联网。 |
| 统计步骤整轨复制放大内存 | 30 秒合成数组的 NumPy 临时分配中，读取后的 RMS 统计路径峰值 15,360,237 B，帧峰值统计 9,632,624 B。 | 分块累计能量，改后分别为 3,841,820 B、2,050,640 B；前者输出样本逐位相同，后者数值差约 2.08×10⁻¹⁷。测的是临时分配，不是进程 RSS；全轨读取与多来源缓存仍未改为流式。 |
| 校时重采样热路径逐样本分配 | 实际调用生产 `WriteSample` 100,000 次，线程累计分配 3,200,000 B，不含反射调用。 | 用同宽浮点/整数位表示写字节，保持 8 种浮点位模式一致；相同调用的该路径分配变为 0 B。减少此处 GC 压力不等于所有录音路径零分配或音质已经达标。 |

旧版已经清理掉的原轨无法通过新校验找回。旧成品没有可信内容摘要时，不自动补一个摘要然后删除原轨；保持现状并提示核对。历史成品仍可打开，这不是批量迁移或恢复承诺。

## 待验证的边界

按风险先后执行，使用可丢弃的独立目录或虚拟机；需要真实设备、播放或录音的部分按用户授权安排。每项记录版本、输入、操作、实际退出码、峰值内存/磁盘、保留文件及失败明细。发现确定问题再做对应修复。

| 优先级与场景 | 验证方法 | 应满足的条件 |
| --- | --- | --- |
| P1：磁盘空间耗尽的不同阶段 | 在限额测试卷分别让原轨写入、混音、发布、笔记写入、状态提交失败；当前仅完成可控流故障注入。 | 已有用户文件不被覆盖；剩余原轨可查；界面不报完整成功，不继续空计时。磁盘完全写满可能使 WAV 头或状态也无法落盘，必须据实报告可恢复程度。 |
| P1：真实长会议与格式上限 | 独立环境连续 30/60/120 分钟录制不同设备格式，另以边界流测试 4 GB；记录各轨、混音和转写内存。评估 RF64 或分段续录方案。 | 时间线不持续漂移，异常停止有明确结果，保留可恢复资料。当前格式仍为普通 RIFF WAV，不承诺无限时长。48 kHz 双声道 float32 单轨约 3 小时 6 分 24 秒达到容量边界，采样率更高时更早。 |
| P1：真实声源与说话人质量 | 固定带人工真值的中文会议样本，覆盖同人跨轨、不同人同时发言、扬声器回声、噪声和重叠，分场景统计 CER、DER、漏句、误并、漏并与待确认时长。 | 保持预先固定的统计口径与失败分母；不能靠降门槛或全部标为未知通过。当前尚不具备全面高质量结论，见 [质量证据](quality.md)。 |
| P1：真实设备更换 | 分别验证 USB 拔插、蓝牙重连、默认麦克风切换，以及固定 ID / default / all_active 三种策略。 | 开关和暂停状态保持，来源清单与成品一致；初始化缺口须测量并报告，不能宣称无缝。已有默认播放角色切换测试不覆盖这些情况。 |
| P2：发布、命名、状态提交间强制中断 | 在独立子进程的文件替换和元数据提交之间设置屏障并终止，逐点重启。另注入旧记录新 WAV 已生成、摘要尚未写入 manifest 的 I/O 故障；断电持久性另在虚拟机验证。 | 原有录音与手写内容保留；不覆盖未归属文件；能明确指出未提交成品或元数据不一致。缺少可信摘要时保守拒绝自动重试、保留原轨，不为了可重试而猜测所有权。当前原子替换和普通异常回滚不构成跨多个文件的事务保证。 |
| P2：长会议转写内存 | 在隔离子进程测合成 1/5/10 分钟与 1/2/4 路输入的 PeakWorkingSet，再安排 1/2 小时完整流水线。 | 分开报告 NumPy 临时分配、进程 RSS、模型占用和跨源缓存。当前去直流与重采样仍读取整轨，缓存全部 16 kHz 来源；2 小时 48 kHz 双声道去直流时可能同时持有约 5.15 GiB 数组，第四路还可能持有前三路约 1.29 GiB 的 16 kHz 副本（尺寸估算，未含模型/其他临时数组），不能用本轮 RMS 改善代替长会议内存验收。 |
| P2：手工同时启动同场 worker | 两个隔离 worker 在处理锁、发布与清理处同步，观察第二个进程等待期间及完成后的状态。 | 不重复覆盖成品，最终状态一致。控制器已防 UI 重复启动，全局处理锁已串行化模型，但不据此宣称手工重复 CLI 的全流程已验证。 |
| P2：外部编辑与输入断点身份 | 保留尺寸和 mtime 后替换合成原轨/片段，另在成品验证与删除之间改文件。 | 不能把旧识别结果当作新输入的正确结果；最后恢复资料应保留。当前输出新增内容校验，输入缓存身份仍主要依赖尺寸和 mtime，也未锁住所有外部编辑器。 |
| P2：历史与诊断状态 | 用 100/1000 个合成会话测菜单响应；构造录制进程崩溃、元数据仍为 recording 的 CLI status 场景。 | 菜单可用且不读错场次；诊断不把陈旧元数据当作存活证据。CLI status 当前读取保存状态，并非控制器存活证明。 |
| P2：驱动长期阻塞与打开中断 | 用独立采集替身卡住端点打开、释放和初始化保存，再让其越过关闭等待边界后返回。 | 不重复交接晚完成来源、不关闭仍在写入的文件、不泄漏等待资源；超时给出明确状态。现有停止超时后可重试测试不等于覆盖真实 COM/驱动永久阻塞。 |
| P2：新机器安装与供应方行为 | 在干净 Windows 环境安装 local/cpu、CUDA、api；真实 API 测试只使用明确允许上传的非敏感音频。核对依赖、TLS、服务错误与模型来源。 | doctor、真实录音和真实转写分别报告；本机通过不代表新机器或供应方已验证。小型说话人模型当前依靠官方 HTTPS 来源、尺寸和本机摘要，不等同于预先固定的上游可信签名。 |

本轮修复未增加浮窗控件或配置项。长期资源优化、文件格式升级及人工质量验收需分别推进，不能通过隐藏限制说明完成。
